## 1. 特质提取机械化 + 怀孕反复得失

### 证据

- 妻子 15682 的 `trait_history.pregnant`（`player_38677.json`）：
  `[{from:868.1.1, to:869.1.1, first:true}, {from:872.1.1, to:876.1.1}, {from:878.1.1, to:null}]`
- 传记原文（第 145 行）：「怀孕自872年起获得、至876年后消失、878年起复得」；
  主角侧（第 25 行）：「为人宽宏大量，自870年起获得；合群，亦自870年起获得……」
- 同一句里 12 项特质连排：`为人野心勃勃、专断、眉清目秀、怯懦、奸猾、节俭的职员、宽宏大量、合群、聪慧、传奇的狂欢者、色欲、放荡。`
  （snap `protagonist.traits`）

### 根因

1. `cache_lib.extract_snapshot`（cache_lib.py:1490-1513）逐档 diff 全部特质，`pregnant` 每次怀孕/分娩都产生一对「获得/消失」区间——生育事实本已由 `child_born` 记忆写足，履历里纯属噪声。
2. `facts.trait_history_lines` 只做区间文案，无类别、无取舍；`facts.traits`/`_traits_at` 返回平铺列表，`biography._profile_lines:466` 直接 `、`.join。
3. 特质类别信息其实拿得到：游戏 `common/traits/*.txt` 每个特质有 `category = personality|education|lifestyle|fame|health|commander|childhood|court_type`，而 `localization.build_trait_names`（localization.py:1100）已在解析同一批文件、只是只取了 `name` 块。

### 方案（全部程序端）

1. `localization.build_trait_names` 扩收 `category`，落 `data/trait_names.json` 的 `categories` 字段；
   `load_trait_names` 的 schema 判定加「无 categories 即重建」（避免用旧表）。
   `data/trait_names.json` 由 `python localization.py traits` 一键重建（现有入口）。
2. 新增 `Facts.trait_groups(cid)`：把特质归为固定几类（性情/才具/仪容/名声/体况/将略/幼性/宫廷），
   每类 ≤5 项超限加「等」；`biography._profile_lines` 的「为人」句改为按类分句：
   `为人：性情野心勃勃、专断；才具聪慧；仪容眉清目秀；名声传奇的狂欢者。`
   （比 P1 清单（`docs/审计_事实文本自然度.md` 四·1）更进一步：类别词由游戏定义直出，不靠提示词。）
3. 新增 `Facts._TRANSIENT_TRAITS = {"pregnant", "recently_birth", "recently_ill", "wounded", "severely_injured"}`
   （体况类、可反复得失者）：`trait_history_lines` 整条跳过；`traits`/`_traits_at`（当前持有）**保留**——
   「878年公主怀孕」是有用事实，只有「履历」不写。
   判定同时看 `category == "health"` 与显式名单（Mod 特质无 category 时靠名单）。
4. 提示词端**不改**（类别与截断都是确定性的）。

### 涉及文件
`localization.py`（build/load_trait_names）、`cache_lib.py`（无改动，若做瞬时态名单可放 facts）、
`facts.py`（trait_groups / trait_history_lines / _traits_at）、`biography.py`（_profile_lines）、`style.py`（若类别词配色需换表则改 `FACT_WORDING`）。

### 验收
- 快照 `protagonist.trait_history` 不含「怀孕」；妻子履历只剩倾国倾城/色欲/合群/放荡。
- 「为人」句出现类别词且同类项 ≤5。

## 2. 主角与妻子「私通」

### 证据

- 主角 5 条 `had_sex` 记忆的对象**全部**是妻子 15682：
  `7272(867.10.22) / 7408(867.11.5) / 15171(869.7.19) / 15658(869.9.8) / 28262(873.9.20)`。
- 传记第 9 行：「私通四次」；第 37 行：「本已借通译交谈的夫妇，反于私通之中生出情愫」；
  第 13 行太史公曰：「私通四次而妻室贵为公主」。

### 根因

- `had_sex` 模板恒为「{name}与{other}有私情。」（style.py:419），不区分对象是否配偶；
- 统计标签 `STATS_LABEL`（style.py:593）把 had_sex / became_lovers 一并记「私通」，
  于是「私通四次」= 四次夫妻同房；
- `_merge_affair_pairs`（facts.py:5568）把同月 had_sex+became_lovers 合并成
  固定串「私通相恋」，同样不看关系；
- `MODULE_TABLE` 把夫妇之情归入「情变私通」模块（facts.py:4580），进入《家室列传》素材。

### 方案（程序端）

1. 新增 `Facts.is_spouse_pair(a, b)`：`b ∈ a.family.{spouse, primary_spouse, former_spouses, concubine, former_concubines}`（缓存当前值 ＋ 新累积字段 `family.ever_spouses`）。
   为保证**跨快照**正确（离异/丧偶后仍应算夫妻），在 cache_lib 的 `extract_snapshot` 里累积
   `rec["family"]["ever_spouses"]`（并集，去重）——一次性小改动，旧缓存缺该字段时回退当前 family。
2. `facts._mem_sentence`：`became_lovers` → 配偶写「{name}与{other}相恋。」（与非配偶同词，无「私」义）；
   `had_sex` → 配偶写「{name}与{other}同房。」，非配偶仍「有私情」。
3. `_merge_affair_pairs`：按对判定，配偶对合并为「{y}年{m}月，{a}与{b}夫妻情笃。」，
   非配偶维持「私通相恋」。
4. `style.STATS_LABEL` 增 `had_sex_spouse`/`became_lovers_spouse` = 「夫妻之情」；
   `_timeline` 生成事件时对配偶对打上该变体（`MODULE_TABLE` 同步把配偶对归「婚配联姻」而非「情变私通」）。
   概览于是写成「夫妻情笃4次」，不再是「私通四次」。
5. 提示词端不改。

### 涉及文件
`cache_lib.py`（ever_spouses）、`facts.py`（is_spouse_pair / _mem_sentence / _merge_affair_pairs / _timeline / MODULE_TABLE）、`style.py`（模板与标签）。

### 验收
- 主角事件句无「与…公主…有私情/私通」；概览无「私通4次」，出现「夫妻之情/夫妻情笃」。
- 非配偶私情（妻子的乔乔/佩拉约/安乔）仍写「私通/有私情」。

### 待拍板
夫妻情事的用词：**推荐**「同房」＋「相恋」＋合并「夫妻情笃」；备选「相守」「恩爱」「结为眷侣」。

## 3. 妻子与妻子私通（自指参与者）

### 证据

- 妻子 6 条 `had_sex` 记忆的 `sex_partner` **等于她本人**：
  `16439(869.11.30) / 16795150(871.1.4) / 16799602(872.2.8) / 28356(873.10.1) / 34840(875.12.10) / 38374(877.1.14)`。
- 全档反查：这 6 个日期**没有任何其他角色**有配对的 `had_sex`（对象槽为空的游戏记录），
  即存档确实没记对方是谁。
- 传记第 157 行：「869年11月30日，西法兰克王国公主埃芒特鲁德·加洛林与西法兰克王国公主埃芒特鲁德·加洛林有私情」；
  第 173 行综述：「869年与乔乔、**又与其自身**」。

### 根因

`facts._mem_sentence`（facts.py:4364-4377）取 `participants[slot]` 后直接当「对方」渲染，
从不校验 `other_id == owner_id`；同名相串即成「A 与 A」。

### 方案（程序端）

`_mem_sentence` 里当解析出的 `other_id == owner_id` 时视为**无对象**（`other = ""`），
并给 `had_sex`/`became_lovers`/`became_soulmates` 三型补「无对象版」模板：

- `had_sex` → 「{name}与人私通。」
- `became_lovers` → 「{name}与人相恋。」
- `became_soulmates` → 略去（无对象即无语义）

同型句并入既有的 `SECRET_TOPICS_NO_TARGET`「与人私通」口径（style.py:503），词面对齐。

### 验收
- 六条自指记录渲染为「…公主与人私通。」，全篇无「A 与 A」式句（可正则断言：句中「与」前后同串）。

### 待拍板
自指私情保留（写「与人私通」，**推荐**——她的私情网络正是第 4 条要写的料）还是整条丢弃？

## 5. 主角手里的牵制（含强弱）全未收集

### 证据

- 存档位置：`relations.active_relations`（本档 12213 条），形如
  `{"first":15682,"second":38677,"active_hook_1":{"type":"favor_hook","expiration_date":"879.8.25"}}`；
  **方向 = `first` 持有对 `second` 的牵制**（证据：Mod 事件 `add_hook{target=npc_2}` 使受害方 `root` 获得
  「干了我老婆」强牵制，本档 `first:38677(主角) second:43961(乔乔)`；
  `house_head_hook` 亦全为 `first:主角 second:诸子`）。
- 主角握有 **9** 条：对乔乔的强牵制「干了我老婆」×1 ＋ 对诸子（阿塔尔/布鲁诺/勒科尔努/达尔马宁/米歇尔/爱德华/希尔德加德/伊丽莎白）的「家主」牵制 ×8。
- 他人对主角 **5** 条：公主「人情」、安乔·瓦斯科涅「至交」＋**强牵制「干了我老婆」**、
  加齐亚·伊尼加「干了我老婆」强牵制、贝拉斯科「人情」。
- 强弱可从定义表判定：游戏 `common/hook_types/00_hook_types.txt`（`strong = yes` 为强）＋
  Mod `longju_exent/common/hook_types/longju_hook_types.txt`（`ganlewodelaopo_hook = {strong = yes}`）；
  名称即本地化键本身（`favor_hook`→人情、`house_head_hook`→家主、`indebted_hook`→蒙恩…实测全部可查）。
- 牵制把柄还补上了记忆系统**没有**的事：安乔与加齐亚都握有主角「干了我老婆」的强牵制，
  即主角另有私通未被 `had_sex` 记忆记录——正是第 2、7 条要用的料。

### 根因

`relations` 节从未被读取：cache_lib 里只有 `EMPTY_CACHE["relations"] = {}`（cache_lib.py:533）
与 `summarize_relations`（cache_lib.py:1993，读的是缓存内字段，非存档节）。facts 层亦无任何 hook 逻辑。

### 方案（程序端）

1. `cache_lib`：

  `culture=0`→`culture_manager.cultures.0.culture_template=akan`→本地化「阿肯」（`akan`=阿肯），

即第 4 条的 1–3 项（并入档案集 ＋ 补 `court_data` ＋ 情人档案行）。

## 7. 秘密：知情者废话与当事人当知情者

### 证据

- 传记第 229 行（用户所引）：「知情者何人？据载，安乔·瓦斯科涅为二子生父，则其必知情；埃马努埃尔既抚养二子，则亦必知情。」
- 数据：`secrets_history["303"]`（`secret_disputed_heritage`，布鲁诺）
  `owner=15682, participants=[15682,12278], known_by=[15682,12278]`；
  `["16777272"]`（米歇尔）同构；`["326"]`（`secret_incest`）`known_by=[15682]` 只有当事人。
- 即：**知情者集合＝当事人集合**，`secret_knowers`（facts.py:2545）只排除 `owner`，
  于是把「生父本人」当作第三方知情者写出，模型只能写出「X 为生父，则必知情」这种同义反复。
- 另一层：本档主角**没有任何自有隐事**，`_article_facts` 的开篇块（biography.py:1081-1087）取 `sec["held"]` 为空 → 不下发；
  开篇只剩共享前缀里一行 `dramatic_facts`（二子血脉），而板块要求却要写「何事、涉及何人、自何时见载、有谁知情」——
  模型无料可依，遂自问自答（第 227/229 行的「就事理推之」「据载」皆属推测）。

### 方案（程序端）

1. `Facts.secret_knowers`：知情者集合改为 `known_by − {owner} − participants`（当事人与持有人均不算第三方知情者）；
   集合为空则返回 `''`（整句略去，不写「无人知情」这类按语——与「缺料按语不进提示词」铁律一致）。
2. `_secrets_facts` 的 `revealed` 判定同步改用新口径；
   若仍想表达「惟当事人自知」，由既有 `held_unrevealed`（仅主角自有隐事）承载，措辞保持「这些隐事至今无人知晓。」。
3. `style.SECRET_TOPICS` 为血统类补指名（避免「血统有争（涉及X）」的括号同位语）：
   `secret_disputed_heritage` → 「所生{target}血统有争」、`secret_unmarried_illegitimate_child` → 「所出{target}血脉存疑」；
   `Facts.secret_topic` 对含 `{target}` 的模板直接补名。
4. `biography._article_facts` 的 secrets 开篇：`held` 为空时改发「家人近臣隐事」前半
   （用既有 `_split_span` 二分，纪事发后半）——开篇不再是空块，模型不必靠一行 `dramatic_facts` 硬凑。
5. 提示词端不改（`RULES["secret"]` 已是正向表述且语义仍成立）。

### 验收
- 血统隐事行不含「知情者：可怖者安乔·瓦斯科涅」（当事人）；
- 开篇块非空（含家人近臣隐事），且无「知情者何人？」素材空缺；
- 无「（涉及X）」式括注（沿用 v29b 判据）。

## 8. 直辖领地：伯爵领与首府男爵领重复

### 证据

- 传记第 9/217 行：「直辖贝阿恩伯爵领、比戈尔伯爵领、波城男爵领、塔布男爵领四地」＋「治所设于波城男爵领」。
- 存档（`tools/out_macron/landed_titles_raw.json`）：
  `b_pau{de_jure_liege:7472(c_bearn), capital_barony:true, capital:7472}`、
  `b_tarbes{…, capital_barony:true, capital:7469(c_bigorre)}`、
  `b_armagnac{…, capital_barony:true, duchy_capital_barony:true, capital:7464}`。
  即：**首府男爵领是所辖伯爵领自带的一枚头衔**，玩家 `landed.domain` 同时列出二者，渲染层照单全收。
- 另有旁证：`realm_capital=7473(b_pau)`，游戏里 `b_pau` 就是治所。

### 根因

`facts._protagonist`（facts.py:5770-5775）对 `ld["domain"]` 逐个 `f.title(tid)` 后直接 `、`.join，
不做「蕴含关系」折叠；`_lt`（facts.py:556）里有 `capital_barony`/`capital` 两个字段可用但未用。

### 方案（程序端）

1. `Facts.domain_titles()`：把 `ld["domain"]` 分为
   - 保留下来的（`c_`/`d_` 等，及**非首府**男爵领——例如自立于他人伯爵领内的男爵领）；
   - 折叠掉的（`capital_barony == true` 且其 `capital` ∈ 直辖集）。
2. `_protagonist` 输出：`直辖3地：贝阿恩伯爵领、比戈尔伯爵领、阿马尼亚克伯爵领，治所波城男爵领`
   ——计数按折叠后算；`b_pau` 只作「治所」出现一次。
   若 `realm_capital` 不在任何直辖伯爵领内（异常档），该男爵领不被折叠。
3. `snap.py` 的 `domain_capitals` 诊断表同步修正（当前把伯爵领自身 id 当首府，纯诊断口径错位）。

### 验收
- 主角档案 `domain` 不含 `b_pau`/`b_tarbes`/`b_armagnac`；`domain_count` 与列出条数一致；
- 「治所」仍写波城男爵领。
