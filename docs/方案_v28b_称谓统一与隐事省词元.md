## 1. 需求二：头衔姓名统一组装框架

### 1.1 唯一出词口

`Facts.person_label(cid, date=None, style=...)`，全项目人物称谓只此一处出词。

| style | 形态 | 用途 |
| --- | --- | --- |
| `full` | 「[前X，]现职Y 姓名」 | 家室/世系/亲属（`kin_label`） |
| `brief` | 「现职Y 姓名」 | 隐事/把柄/要员隐事/时间线/记忆句/死句/语言句 |
| `event` | 「现职Y 姓名」按**事件日期**取职 | 恩怨史事件重渲染（v14） |
| `office` | 与 `brief` 同形（v28b 起保留宗族姓） | 宫廷僚属任职行（v23；用户拍板 6） |

### 1.2 不变量

1. **不返回占位**：名不可考（`某人`/`一位人物`/`名讳不详`）时返回 `''`，调用方整条略去。
2. **裸官职词不出词**：官职词须带头衔地名/国号才作前缀（修「领袖叠溪寋」）。
3. **不叠前缀**：名字已含称号/绰号者不重复（天皇座子女、绰号）。
4. **日期锚点**：`brief`/`office` 取 `_anchor_date`（死者取卒日、在世取 as_of）；
   `event` 取事件日；`full` 另比前头衔层级。
5. **结果稳定 + memo**：`(cid, date, style)` 缓存（`kin_label` 单次构建被调数百次）。
6. **单一出口**：biography 侧不再拼 `office+name`（改取 facts 组好的 `label` 字段）。

### 1.3 收编的散装拼装点

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| `biography._profile_lines` 名号句 | `head = f"{p['office']}{name}"` | `head = p["label"]`（旧缓存回退旧式） |
| `biography._assassin_kill_lines` / 刺客列传开篇名录 | `disp = f"{off}{nm}"` | `disp = k.get("label")` |
| `facts._villain_chains` | `off + vname` | `person_label(victim, "brief")` |
| `facts._mem_sentence` owner/other | `name_with_regnal` | `person_label(..., "brief")` |
| `facts._death_sentence` | `name_with_regnal` | `person_label(..., "brief")` |
| `facts.death_clause` / `assassination_method` 施事者 | `name_or` | `person_label(..., "brief")` |
| `facts.language_relation_line(s)` | `name_or` | `person_label(..., "brief")` |
| `facts._protagonist` / `_character_profiles` / `_killed_by_player` | 只给 `name`+`office` | 另给 `label`（biography 直接用） |
| `facts._year_summary` | 以「姓名+动词」解析谋杀/添丁 | 先剥去姓名前的官职称谓再解析；同一行主角称谓只写一次 |

### 1.4 顺带修掉的缺陷

- 死者称谓：「领袖叠溪寋」→「农民起义领袖叠溪寋」；无起义名可考时退回显示名。
- office 式去姓：「唐皇帝漼」→「唐皇帝李漼」（单字名不再去姓）。
- 占位串进制：「一位人物」不再作为称谓出现。

## 2. 需求一：隐事板块省词元

### 2.1 做法

1. **按人合并**（`Facts.secret_lines`）：同一持有人的多桩隐事并成一行，持有人只写一次 —
   「商州刺史陆荣廷有隐事两桩：科举舞弊（涉及岭西观察使樊骥）；科举舞弊（涉及唐皇帝李漼，自873年见载）。」
2. **把柄按对方持有人归并**：「{主角}握有{对方}的把柄：A；B。」
3. **知情者按年升序**（`secret_knowers`），同年并列只写一次年份（「（同年）」）。
4. **规则收窄**（拍板 4）：`SECRET_RULE` 只随《阴私录》《朝局风云录》下发，
   其余板块 system 每请求少 78 字符（田所：14 次请求 ≈ 1.1k 字符/批次）。
5. 见载年表（`events`）按拍板 2 保留，事件行同样使用统一称谓。

### 2.2 实测（`experiments/measure_secrets.py`，从熔件重建缓存）

陆氏 @878.6.5（`secrets_history` 173 条）：

| 块 | 新（v28b） | 旧式（v28 逐桩一行） |
| --- | --- | --- |
| `held` + `kinsmen` + `known` | 73 字符 / 2 行 | 100 字符 / 4 行（含独立知情者句） |

## 3. 成本实测（称谓统一的词元代价，如实记录）

| 项 | 陆氏 | 田所 | 田所2 |
| --- | --- | --- | --- |
| 共享前缀（v28 → v28b） | 845 → **869**（+24） | 1573 → **1668**（+95） | 1467 → **1555**（+88） |
| system 每请求 | 628（隐事板块 706） | 同左 | 同左 |

自然度 P1 各批次仍按「字符数不增」验收（见审计文档 §六）。

## 5. 调研：起义领袖的称谓来源（拍板 7）

存档侧（`melt.faction_manager.factions`，键为派系 id）：

```jsonc
"36": {"type": "peasant_faction", "target": 10529, "leader": 43603,
       "special_character": 43603, "power": 1000,
       "title_members": [{"county": 14534}, {"county": 14538}],
       "variables": {"data": [{"flag": "faction_faith",   "data": {"identity": 136}},
                              {"flag": "faction_culture", "data": {"identity": 166}}]}}
```

实测（陆氏 melt_870/871）：43603（叠溪寋）即该 `peasant_faction` 的领袖，power 896→1000。
三战役出现的派系类型：`peasant_faction` / `escalated_peasant_faction` / `populist_faction` /
`nomadic_faction`（起义类）与 `independence_faction` / `claimant_faction` /
`liberty_faction` / `nation_fracturing_faction` / `replace_ceremonial_regent_faction`
（封臣派系，领袖本有领地头衔，不给起义称谓）。

游戏本地化键（`data/localization.json`，供对照）：
`FACTION_PEASANT_TITLE_NAME`=农民叛乱、`FACTION_POPULIST_REVOLT_TITLE_NAME`=民粹暴动、
`FACTION_NOMADIC_REVOLT_TITLE_NAME`=游牧民叛乱、`peasant_leader_title_name`=「X巾起义」、
`faction_leader_male/female`=领袖（死者 `dead_data.flavor` 即此键，故此前写出裸词「领袖」）。

落实：新增 `cache["factions"]`（`cache_lib._diff_factions`，逐档差分；起义类领袖一律记录 —
叛乱领袖常在身故后才进入传主视野，先按相关集过滤会漏掉其起义身份），
`Facts.faction_word(cid)` → 中文起义名（用户定稿用「起义」）：
`peasant_faction`/`escalated_peasant_faction` → 农民起义、`populist_faction` → 民粹起义、
`nomadic_faction` → 游牧民起义。称谓形态：「农民起义领袖叠溪寋」。
