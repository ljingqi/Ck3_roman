## 问题 1：主角由哥特人改为诺斯人，传记通篇写作「诺斯人」

### 根因（存档记了变迁，缓存只留最后一档）

熔件逐档实测（id=38691）：

| 快照 | culture | 文化名 | languages |
|---|---|---|---|
| 868 / 869 / 870 | **51** | **gothic（哥特）** | language_central_germanic |
| 871 起至 888 | 161 | norse（诺斯） | language_central_germanic, **language_norse** |

即：**871 年由哥特改宗诺斯**（同时习得诺斯语）。但 `cache_lib.extract_snapshot`：

- 文化只有「有值即覆盖」一条路径（cache_lib.py:1452–1456）：
  `if c.get("culture") is not None: rec["culture"] = c.get(...)`，
  且首见时只写一次（cache_lib.py:1436）；
- 信仰却有完整的变迁记录 `faith_history`（cache_lib.py:1438–1440 首见 +
  1457–1465 逐档差分，注释自述「游戏不为玩家改信留任何记忆，逐档差分是唯一来源」）。

于是 `Facts.culture()` / `_profile_lines` 只能给出**当前**族属「诺斯人」，
`titles_held`、语言行也随之全篇按诺斯人写。模型没有可写的变迁，只能从出生起就写诺斯人
（第 1 个十年第 9 行、第 2 个十年第 9 行）。

### 修复（程序端，纯数据）

1. **`cache_lib` 增 `culture_history`**，与 `faith_history` 同构（首见记 `{from: 日期, culture: id}`，
   此后逐档差分追加）；死档 `culture` 被游戏清空时沿用「缺失保留最近已知值」的既有策略。
2. **一次性迁移脚本**（仿 `experiments/fix_house_name.py`）回填 38691 及其家族 21 份快照的族属变迁；
   以后新战役自动积累。
3. **facts 渲染族属变迁行**（人物档案内，与语言行并列）：

   ```
   族属：哥特人（至870年），871年起为诺斯人。
   ```

   语言行按同一分界分段：`母语中日耳曼语（至870年），871年起母语诺斯语，兼通中日耳曼语。`
   ——两行都由程序按 `culture_history` 与逐档 `languages` 直出，提示词不承担判断。
4. **各篇不再自行推断族属**：`titles_held` / 开篇的「诺斯人」目前来自 `protagonist.culture`，
   改为「按 as_of 取当期族属」（与头衔、官职同一 `_anchor_date` 口径）。
5. 提示词（可选、正向）：《本纪》开篇板块要求补一句
   「传主族属与母语若在生年中有变更，写出改属的年份与前后族名与语名。」
   —— 若第 3 步的档案行已足够显眼，可不加（prompt-last 原则）。

## 问题 2：主角头衔「雅尔」被写成通用的「大酋长」

### 根因（**键名叫 count_*，游戏里 tier 却是 duchy** —— 我们的层级词从不查 flavorization）

**存档实测（决定性证据，取自存档信封 `meta_*`）**：

```
melt_878  meta_title_name = 罗加兰酋邦        meta_player_tier = 2   meta_player_name = 酋长崔佛
melt_888  meta_title_name = 居拉辛斯勒格雅尔国  meta_player_tier = 3   meta_player_name = 雅尔崔佛
```

游戏对这位**公国级**诺斯统治者显示的正是 **雅尔** / **雅尔国**，我们渲染成
「居拉辛斯勒格**大酋长**」与「居拉辛斯勒格**公国**」。

游戏侧的真实规则在 `game/common/flavorization/00_title_holders.txt` 的 Norse 段：

```
count_feudal_male_norse   = { type=character gender=male   tier = duchy  priority = 30  governments={feudal,tribal,administrative}  name_lists={name_list_norse} }
count_feudal_female_norse = { … tier = duchy … }
county_feudal_norse       = { type=title     tier = duchy  priority = 30  … }
duke_tribal_male          = { type=character tier=duchy    priority = 26  governments={tribal_government …} }   ← 我们现在取到的词
```

**键名沿用 `count_*`，`tier` 字段却是 `duchy`**；游戏按 priority 取最高者（30 > 26）→ 雅尔。
我们这边：

- `Facts._nomad_office_word`（facts.py:1862–1885）对部落政体只试 `<tier>_tribal_<gender>`
  → `duke_tribal_male` = **大酋长**；
- `Facts._office_word` 的收尾回退（facts.py:1789–1797）只试 `<tier>_<政体>_male` / `_feudal_male`；
- 文化专属词只有 `_culture_office_word`（facts.py:1818–1839），且**只认 chinese 一族**
  （`_CULTURE_TITLE_FAMILY`）。
- 头衔名的层级后缀走 `localization.tier_word`（localization.py:1182–1207），只查
  `culture_titles` 与 `<政体>_salary_rank_*`，最后落到通用表 `公国`（localization.py:1171）。

**flavorization 所需的匹配键熔件里都有**：`culture_manager.cultures[X]` 实测含
`name_list`（`name_list_akan`…）、`heritage`、`language`、`traditions`、`ethos`
（`_heritage_of` 已在用 heritage，facts.py:1848–1860）。

### 修复（程序端，新增 flavorization 解析器）

1. **新增 `flavorization.py`**（或并入 `localization.py`）：解析游戏 + 启用 Mod 的
   `common/flavorization/*.txt`，索引 `(type=character|title, tier, gender)` →
   `[{priority, governments, heritages, name_lists, rules, loc_key}]`。
   模块指纹变更即重建（沿用 `localization.load_localization_table` 的口径与 `loc_miss.log` 风格）。
2. **`_office_word` 改为**：先 flavorization 命中（按 priority 排序，条件取
   `governments` × 文化的 `name_lists/heritage`），未命中再走现有
   `_nomad_office_word` → `_culture_office_word` → 政体前缀链。
3. **头衔名层级词 `tier_word` 同步查 flavorization 的 `type=title` 项**
   → 「居拉辛斯勒格雅尔国」而非「居拉辛斯勒格公国」。
4. **回头把 `_ASIAN_HERITAGE_TPL`（facts.py:547–564）、`_CULTURE_OFFICE_KEYS`、
   `_NOMAD_LIKE_GOVS` 三条硬编码逐步降级为「兜底」**（flavorization 解析成功即不再需要），
   降低后续 Mod / 文化新增的维护成本。
5. **低风险过渡方案**（若不想一次上解析器）：只给 `norse` 加一条数据：公国级 → 雅尔 /
   雅尔国（键 `count_feudal_male_norse` / `county_feudal_norse`）。**建议直接上解析器**，
   因为同一类错配在盎格鲁-撒克逊 / 英语 / 俄语 / 日语等族上同样会发生
   （实测本地化表中这些族都有专属层级词，我们的代码一条都不查）。

## 问题 3：「吃了败仗 / 打了胜仗」这类文不文白不白的措辞渗进正文

### 根因（**事实层模板即游戏口语**，模型逐字照抄）

`facts.MEMORY_TEMPLATES`（facts.py:176–177）：

```python
"battle_won_memory":  "{name}打了胜仗。",
"battle_lost_memory": "{name}吃了败仗。",
```

同族还有 `{name}主动开战。` / `{name}被迫应战。` / `{name}助盟友作战。`（facts.py:178–182）。
统计标签同源（facts.py:5252 `"battle_lost_memory": "败仗"`），进入【概览】
（`decade_stats`）与总纲。

**证据**：本轮提示词 `大事年表` 中共 3×「打了胜仗」、3×「吃了败仗」
（prompts.log:1122、1150…）；正文照抄：「886年12月13日，他**吃了败仗**」
（第 2 个十年第 67 行）、「佛罗西**吃了败仗**」（第 1 个十年第 45 行）、
总纲「胜仗3次…开战1次」（第 2 个十年第 13 行）。

### 修复（程序端：改词表，不改提示词）

1. **战事词表统一为「史笔中性」**（一并在问题 11 的 `style.py` 内集中维护）：

   | 键 | 现文 | 建议 |
   |---|---|---|
   | `battle_won_memory` | 打了胜仗 | **取胜** |
   | `battle_lost_memory` | 吃了败仗 | **失利** |
   | `war_won` | 赢得战争 | 赢得战争（保留，语义是战争非战斗） |
   | `war_lost` | 战败 | 战败（保留） |
   | `offensive_war` | 主动开战 | 兴兵来攻（或保留） |
   | `defensive_war` | 被迫应战 | 被迫应战（保留） |
   | `_STATS_LABEL` 胜仗/败仗 | 胜仗/败仗 | **取胜/失利** |

   取值理由：与既有 `战败/赢得战争/成婚/添子` 的史笔语域一致；
   「打了/吃了」是游戏 UI 口语，与纪传体格格不入。
2. **同表全文自查**：`MEMORY_TEMPLATES` 全部 60 余条按「文言雅洁、四字以内」过一遍
   （如 `获释出狱`→`获释`，`学业有成`/`完成成人礼` 保留），一次改净。
3. **不改提示词**：模型照抄是因为事实就长这样；事实改完，正文自然跟着改
   （符合「事实层的确定性改写优先做在渲染期」）。

## 问题 4：正文大量「资料未载」——**是提示词自己教的**

### 根因（提示词与档案行同时种下这个词）

`logs/prompts.log` 全量统计：

| 短语 | 提示词出现次数 |
|---|---|
| **资料未载** | **44** |
| 资料未提供 | 16 |
| 资料不足 | 16 |

来源共五处，全部是「写给模型的字」：

| # | 位置 | 原文 |
|---|---|---|
| ① | biography.py:62–65 `WORLD_FRAME_RULE` | 「…一律以资料为准, **资料未载之处行文径入下一事**。」（每条请求都带） |
| ② | biography.py:54–58 `NONFICTION_RULE` | 「**资料未提供的内容简写或略去**。」（每条请求都带） |
| ③ | biography.py:1240–1242 `_decade_theme_note` | 「**资料不足的内容简写或略去**。」（每条请求都带） |
| ④ | biography.py:747 `_profile_lines` | 程序直出「**先世资料未载**」（自定义出身者的家世句，每条请求都带） |
| ⑤ | biography.py:1401 `custom_note` | 「本篇传主的**先世资料未载**: 开篇以…」 |

**证据链**：档案行 `先世资料未载。` 出现在 prompts.log:26/113/217/326/414/534/602/704/790/883/997/1086/1209/1323/1441/1544 共 16 次；
正文里模型据此派生出「资料未载其详」（第 1 个十年第 35 行）、「谁人囚之,资料未载; 囚为何故,资料未载」（第 47 行）、
「资料不载」（4 次）、「资料未详」（1 次）。第 2 个十年 20 次，第 1 个十年 13 次。
**即：模型不是在「抱怨缺料」，而是在复读提示词的口头禅。**

### 修复（提示词改写 + 档案行删除）

1. **①②③ 三处「缺料按语」全部删去，改写为正向的写法要求**（不出现「资料未载/未提供/不足」）：

   - `WORLD_FRAME_RULE` →
     「「平行世界规则」: 本传所写世界完全由本提示词资料构成, 与任何真实历史无关;
     所有人物、家族、官职、事件、日期、数字一律按资料给出的写法书写。」
     （删去后半句「资料未载之处行文径入下一事」）
   - `NONFICTION_RULE` →
     「「非虚构铁律」: 资料给出的人名、地名、日期、数字、事件一律按资料原样书写;
     人物的心理、对话、场景、细节在资料允许的范围内合情演绎;
     叙述依资料可据之处依次推进, 以已知的人事时地把场面写足。」
   - `_decade_theme_note` 尾句 → 「各篇正文围绕这些主题取材，主题相关的事件写出戏剧张力。」
     （删去「资料不足的内容简写或略去」）
2. **④ 程序端删除「先世资料未载」这一行**（biography.py:747）：自定义出身即无父母谱系，
   **无料即不下发**（与 `_set_block`「无料即不下发该块」同一原则）。开篇改由
   `NARRATIVE_FOCUS_RULE`（biography.py:68–71「每一句都落在具体的人、时、地、事上」）兜住写法。
3. **⑤ 删除 `custom_note` 的「先世资料未载」前置句**，只保留正向指示范文：
   「开篇以「起于何时何地、如何发迹」为纲书写其出身，父母名姓与祖上事迹以资料载明者为限。」
4. **加一条回归检查（不写进提示词）**：`tools/verify_fast.py` 增断言——输出正文与
   prompts.log 中 `资料未载|资料不载|史料未详|史无可考` 计数为 0（或低于阈值），
   改完即回归可量化。
5. 说明：**不做输出侧正则清洗**。按语嵌在句子里，正则删改会破坏句子；根因在输入侧，改输入即可。

## 问题 5：被囚 / 获释分两行，应合并为「某日被囚，X 后获释」

### 现状与根因（事实层把一次监禁拆成两条独立事件）

`MEMORY_TEMPLATES`（facts.py:153–155）三条独立模板，`_timeline` 按记忆逐条输出：

```
878年2月6日，戈迪娜·迭戈斯被囚。          ← 被囚
879年1月21日，维格迪丝·阿尔夫耶尔斯多蒂尔被囚。
879年2月4日，维格迪丝·阿尔夫耶尔斯多蒂尔获释出狱。   ← 获释（独立一行）
879年5月5日，阿斯图里亚斯-德桑蒂利亚纳伯爵迭戈·罗德里戈斯被囚。
879年8月20日，阿斯图里亚斯-德桑蒂利亚纳伯爵迭戈·罗德里戈斯获释出狱。
880年，戈迪娜·迭戈斯获释出狱。
```
（prompts.log:1117、1126、1128、1132、1134、1135…，本轮共 7 次「被囚」、7 次「获释出狱」）

**已有的可复用机制**：`Facts.imprison_duration`（facts.py:3317–3374）**已经**能从
「受害者自身 `imprisoned` / `released_from_prison_memory` + 主角 `imprisoned_other` 兜底」
算出「N年M个月」，但**只在「卒时仍在狱中」的死亡句里用**（facts.py:3408–3416，如
「囚禁4年3个月后被烧死」——本轮输出第 2 个十年第 227 行已出现该效果）。
缺的只是把它用在**活着出狱**的常规事件上。

参与者结构实测（`experiments/diag_philip4_pairs.py`，本轮真值）：

```
878.2.6   imprisoned   owner=戈迪娜·卡斯特利亚(17039)   parts={'imprisoner': 崔佛·菲利普}
879.1.21  imprisoned   owner=维格迪丝·卢萨克伊庞(48022)  parts={'imprisoner': 崔佛·菲利普}
879.2.4   released     owner=维格迪丝·卢萨克伊庞(48022)  parts={'imprisoner': 崔佛·菲利普}
```
→ 同 owner + 同 imprisoner + 入狱日 < 出狱日 即可确定配对。

### 修复（程序端，改 `facts._timeline`）

1. **新增 `_pair_imprisonment(events, f)`**，在 `_merge_same_day_events` 之前跑：
   - 按被囚者（受害者）聚合三型记忆（`imprisoned` 受害者视角 / `imprisoned_other` 施囚者视角 /
     `released_from_prison_memory`），按日期排序，**入狱 → 其后最近一次获释**配成一对；
   - 合并为一行：`873年5月13日，埃里克尔·霍达兰被崔佛·菲利普囚，三日后获释。`
   - 至 as_of 仍未出狱：`…被囚，至888年仍在狱中。`
2. **时长档位**（沿用 `imprison_duration` 的月差算法，向下扩展到日）：

   | 时长 | 写法 |
   |---|---|
   | < 1 个月 | `N日后获释` |
   | < 1 年 | `N个月后获释` |
   | ≥ 1 年 | `N年M个月后获释` |

3. **删除独立的获释行**（配对成功后不再单出），`imprisoned_other` 的「甲囚禁乙」行一并并入
   （避免「甲囚禁乙」+「乙被囚」双写）。
4. **`imprison_duration` 与新函数合并为一个出口**（`Facts.imprison_interval`），
   死亡句与常规事件共用同一份配对逻辑，防止两处口径漂移。
5. 提示词不动：合并后事实本身已是完整叙事，模型自然照写。

## 问题 6：大事记重复事件（同一件事的正反两方记忆）

### 根因（镜像对未被识别；现有去重只覆盖死亡/出生）

`_timeline` 的去重键是 `(type, date, participants 集)`（facts.py:5039–5044），
**正反两方是不同 type**，故全部漏网。本轮实测镜像对（`diag_philip4_pairs.py` 真值）：

| 日期 | 一方记忆 | 另一方记忆 | 配对键（实测） |
|---|---|---|---|

## 问题 8：刺客列传反复出现「居拉辛斯勒格大酋长崔佛·菲利普」

### 根因（死句由程序把凶手全称谓嵌进每一句）

`facts.death_clause`（facts.py:697–722）在 `_DEATH_KILLER_VERB` / `_DEATH_EXECUTOR_VERB`
命中时输出「被**{凶手全称谓}**{动词}」；`_killed` 对每名死者各调一次 `_death_sentence`
（facts.py:6569–6582）。凶手在本篇**恒为主角**，于是称谓被复制 14 次。

**证据**：prompts.log 中「居拉辛斯勒格大酋长崔佛·菲利普」出现 **163 次**，
其中「被居拉辛斯勒格大酋长崔佛·菲利普烧死」**21 次**、「…斩首」2 次；
正文里每个死者条目都以该全称谓开头（第 2 个十年第 201–237 行）。

### 修复（程序端：刺客列传专用省略式）

1. **`_death_sentence(f, cid, omit_killer=True)`**：走 `death_clause` 的**动词分支**，
   不填凶手名 → 「死于878年2月9日，**被烧死**。」
   （`_killed` 专用；时间线、恩怨史、朝局等仍用全称谓，保持全篇称谓一致铁律不破。）
2. **在刺客列传开篇（程序行）点名一次施事**：
   「崔佛·菲利普一生所杀十四人，皆死于其手。」
   正文里模型再提主角时自然用「他」或省略主语。
3. 可选（正向提示词）：`SECTION_REQ["assassins"]` 补「本篇以死者为句子的主语，死法写清即可」。
   —— 程序端已去掉重复源，此句可省。
4. **顺带**：`k["death"]` 里现有「被…（死于X）」的嵌套括注（如
   「被居拉辛斯勒格大酋长崔佛·菲利普斩首（死于沃巴瑟）」），省略凶手后更干净。

## 待确认项

1. **族属变迁的呈现粒度**：只在人物档案写「族属：哥特人（至870年），871年起为诺斯人」，
   还是开篇也要点出改宗缘由？（数据只有年份，缘由无据，建议只写事实。）
   母语是否随之分阶段写（870 前中日耳曼语 → 871 起诺斯语）？
2. **问题 2 的路线**：直接上 flavorization 解析器（收益广、风险高），
   还是先做 Norse 单族特例（低风险）？若上解析器，是否需要同时接管
   `_ASIAN_HERITAGE_TPL` / `_CULTURE_OFFICE_KEYS` / `_NOMAD_LIKE_GOVS` 三处硬编码？
3. **问题 3 的替换词**：战斗用「取胜 / 失利」还是更简的「胜 / 败」？
   `offensive_war` 的「主动开战」是否一并改为「兴兵来攻」？
4. **问题 4 的边界**：确实关键但无据之处（例如「谁人囚之」），
   是否允许保留一句极简考语？还是**一律归零**（建议归零，模型会自行含蓄处理）。
5. **问题 5 已出狱者**：合并句用「三日后获释」这类**时长**表述，
   还是「于5月16日获释」这类**日期**表述？（用户原话倾向时长，建议时长 + 括注日期。）
6. **问题 7 的合并阈值**：只并「共父/共母/同胞」，还是把「配偶同死」「同一案被处决」
   也算同组？（建议先只并血亲，配偶另议。）
7. **问题 8 的省略范围**：刺客列传全篇省略凶手称谓（只在开篇点名一次），
   是否也适用于《朝局风云录》里主角被处决/囚禁的同类句子？（建议只改刺客列传。）
8. **问题 11 的边界**：`style.py` 只放 LLM 提示词（A/B/C/E），
   还是连事实层措辞表（D：`MEMORY_TEMPLATES` / 死因词 / 统计标签）一起放？
   （建议连 D 一起放，因为问题 3 证明「事实措辞即文风」。）
9. **重跑范围**：只重跑 `菲利普`（2 篇十年传记）验证，还是四个历史测试集全量回归？
10. **问题 12 权重**：教义允许时给「献祭」加权（如双份），还是严格等概率？
