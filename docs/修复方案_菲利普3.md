## 问题 1：崔佛·富兰克林松统治 21 年（936–957）却没有生成任何十年小传

### 根因（已定位，属判重键撞车）

十年传记的「已生成」判定 `_generated_decades_on_disk`（pipeline.py:931–946）与输出文件名 `output_paths`（pipeline.py:557–578）都以 **`name_full` 作为人物标识**：

```python
pname = rec.get("name_full") or rec.get("name_zh") ...   # pipeline.py:563 / 938
pat = re.compile(re.escape(pname) + r"_传记_第(\d+)个十年_.*\.md$")
```

而祖父崔佛·菲利普（38725）与孙崔佛·富兰克林松（16836221）的缓存 `name_full` **都是「菲利普崔佛」**（同宗同名 + 姓序拼接错误，见问题 4）。因此孙子的十年判定直接命中祖父已生成的文件（`菲利普崔佛_传记_第1个十年_892_01_01.md` 等 4 篇），被判「已生成」而全部跳过。

日志证据：
- 936–957 逐年并入（journal.log 15226–16755 行：`并入 936.1.1 玩家 乡绅崔佛 (id=16836221)` … `并入 957.1.1`）期间，**没有任何** `[触发] … 数据已满第N个十年` 日志；
- 946.1.1（12:42:36）、956.1.1（13:31:04）并入时本应触发第 1、2 个十年，均被静默跳过；
- 13:39:32 死亡检测后才出现 `[十年] 玩家 乡绅崔佛 (id=16836221) 数据已满十年 [1, 2] 但已死亡, 按设计跳过` —— 说明系统直到他死后才第一次意识到他有满十年数据。

### 修复

1. **十年判重与文件命名改以 `(player_id, decade)` 为唯一键**：文件名加入玩家 id 或生年（如 `菲利普崔佛(872)_传记_第1个十年_946_01_01.md` 或 `player_16836221_传记_…`），`_generated_decades_on_disk` 同步按新模式解析，不再用纯姓名匹配。
2. **顺带修正十年截止日命名漂移**：现目录里 `第2个十年_912` 与 `第3个十年_912` 同名截止（历史 `_decade_cutoff` 版本漂移所致，pipeline.py:581–594 现行公式 `起始年+decade×10` 会给出 902，需与旧文件核对重命名）。重命名后按新命名规则重新生成孙子缺失的第 1、2 篇十年小传（数据已在他缓存中，直接 `pipeline.py bio 16836221 --decade 1/2 --force` 级逻辑补出即可，无需重新熔化存档）。
3. `htmlview` 的人物分组同样用 `name_full`/文件名（htmlview.py `_person_of`），同名牌会让两代崔佛在阅读页混为一组，一并改为按文件内 player_id/生年标注分组。

## 问题 2：模型抓不住「只当了一天周皇朝皇帝」的戏剧感

### 根因（事实在提示词里，但被埋没）

存档 title history 完整记录了这段（melt_936 实测）：

```
tid=14036 h_china: 935.11.4 holder=16836221 (appointment_succession)
                   935.11.5 holder=16836221 type=destroyed   ← 登位次日皇朝被毁
```

提示词里其实有（prompts.log:67732，崔佛·富兰克林松 957 终传）：

```
历任：…；935年11月4日任周皇朝之主；935年11月5日任菲利普家族之主（毁弃中华皇朝）；…
```

但：① 这一戏剧点埋在 6 段历任列表中间；② 主角大事年表只收记忆类事件，头衔变更不进年表，935 年 11 月没有任何事件条目；③ 提示词无任何引导，模型注意力被 21 年「交行台/交国」统治占满。于是 957 终传正文（`菲利普崔佛_终传_957_06_12.md`）对此一字未提。

### 修复

1. **facts.py 新增「戏剧性事实」检测**（数据驱动，无硬编码战役）：遍历主角 `_hold_intervals`，凡持有 h_/e_ 级头衔不足 N 天（如 30 天）即失去/被毁的区间，渲染独立高亮块，置于【人物档案】之后：

   【戏剧性事件】935年11月4日承袭周皇朝，翌日（11月5日）皇朝被毁，在位仅一日。

2. **历任渲染补任期标注**：短任期段写明「在位仅X日」，让时长显性化。
3. **《朝局风云录》数据源 `_realm_facts`（facts.py:2140）已按 title history 精确日期收录 holder 变化**，确认该段会以「周皇朝：935.11.4：崔佛·富兰克林松，935.11.5：无（皇朝被毁）」出现；若快照粒度导致缺失，则把 h_/e_ 头衔的 destroy 事件单独补入朝局动态。
4. 语气遵循正向表述：提示词写「在位时长一并写出」（而不是「不要漏写」）。

## 问题 3：模型 get 不到「富兰克林纳了父亲的妾/妻」

### 根因（数据在缓存里，但提示词没有关系标注）

缓存 family 数据完整：富兰克林（16820097）的 `family.concubine = [33598277, 16837063]`，其中 **16837063 = 马乌戈热塔·皮雅斯特 = 其父崔佛·菲利普的正妻**（崔佛 922 档 `family.primary_spouse=[16837063]`，提示词 922 年显示「妻室：马乌戈热塔·皮雅斯特」）。但 935 终传提示词只渲染：

```
妾：善德、马乌戈热塔·皮雅斯特        （prompts.log:38935）
```

没有「她原为父之妻」的标注，模型无从串联，正文只把她当普通妾一笔带过（还把崔佛的妾徐真艳误写成「乳母」，见问题 7 注）。

### 修复

1. **妻/妾/前妻渲染时做关系标注**：渲染 `妻室/妾/前妾/前妻` 名单时，对每个对象检查其与主角父亲（及祖父/兄弟等近亲）的婚姻史（缓存 family 反向交叉：对象在父的 `primary_spouse/concubine/former_*` 中出现过）→ 追加括注：

   ```
   妾：善德、马乌戈热塔·皮雅斯特（原为父崔佛·菲利普之妻）
   ```

2. **家室列传/家室档案**对这类「家族内部转手」人物显式书写「先事X，后归Y」，作为家室恩怨主线之一。
3. 可选：并入问题 2 的【戏剧性事件】块。

## 问题 4：人名组装大修 —— 统一成一段函数（游戏同规则）

### 根因（姓名逻辑分散 6+ 处，且多处产出错序名）

1. **`cache_lib.extract_snapshot`（cache_lib.py:1017）**：`rec["name_full"] = h + rec["name_zh"]` —— 无条件「姓+名」拼接、无分隔符、不看文化名序 → 西式名也被存成「菲利普崔佛」。
2. **`cache_lib.resolve_full_name`（563–592）**：无条件 `姓+名`，`summarize_relations` 等处用它。
3. **`cache_lib.name_display`（631–665）**：名序正确（东方姓前、西方名·姓），但文化缺失时回退 `name_full`（错序）。实测父 38725 在孙辈缓存里 `culture=None` → 提示词输出「父：菲利普崔佛」（prompts.log:38938），模型照抄为「父讳菲利普崔佛」。
4. **`facts.patronym`（facts.py:1224–1244）依赖文化模板**：玩家角色在存档中**根本没有 culture 字段**（melt_935 实测 16820097 无 culture，而其子 16836221 有 161=norse），死者 culture 又被游戏清空 → 父名推断失败 → 富兰克林·崔佛松 渲染成「富兰克林·菲利普」（prompts.log:67729）。
5. **`biography.py:492` 内联拼接** `full = f"{n}{nm}"`（群英录用）。
6. **`pipeline.py:563/938`** 用 `name_full` 做文件名（问题 1 的同名撞车即由此来）。
7. `build_names.py`、`htmlview` 各自再拼一遍。

### 修复（统一出口）

1. **新增唯一姓名函数**（放 cache_lib，供 facts/biography/pipeline/htmlview 全量调用）：

   ```
   display_name(cid) → 按游戏规则的显示名
   ```
   规则链：
   - 父名制文化（patronym_rules.json 有模板）→ `名·父名`（富兰克林·崔佛松）；父名来自父名 + pm/sm 前后缀，性别取 pf/sf；
   - 其它文化按 `name_order_convention`：东方（DYNASTY_ALWAYS_FIRST/JAPANESE）→ `姓+名`（边诚），西方 → `名·姓`（崔佛·菲利普、巴沙尔·冯·大马士革）；
   - **文化缺失时按 父 → 子女 → 同胞 → 配偶 → 宗族成员 链推断**（玩家/死者均覆盖；实测玩家本人无 culture 时可经子女 161=norse 反推），推断失败**宁可省略也不输出错序拼接**。
2. **`name_full` 改为按名序渲染的正确完整名**（存储时即用 display_name 结果），废除无条件 `h + nm`；`resolve_full_name` 内部改调 display_name；历史缓存用一次性迁移脚本重写 `name_full`（仿 experiments/fix_house_name.py）。
3. **`facts.patronym` 文化模板推断链加长**：自己 → 父 → 任一子女 → 语言反查（language_norse→norse）→ 宗族默认。
4. 删除散落内联拼接（biography.py:492 等），全部走 display_name。
5. `build_names.py`（names.json）与 `htmlview` 同步改调统一函数。

## 问题 5：宝物志里太多「毛皮」凑数

### 根因（过滤条件不查宝物类型）

`family_artifacts`（facts.py:1010–1078）只过滤：稀有度 ∈ {masterwork, illustrious, legendary} + 持有者 ∈ 相关集 + 曾跨宗族流转。存档 3339 件宝物中 `animal_hide`(147) / `animal_hide_big`(103) / `animal_trinket`(28，角/鹿角) / `animal_skull`(2) 多为 masterwork 且大量跨宗族（实测「强大羚羊的毛皮」「狂野狍子的毛皮」均入列），于是宝物志被狩猎战利品淹没（见 `菲利普富兰克林_终传_935_11_04.md` 宝物段）。

### 修复

1. **类型黑名单**：排除 `animal_hide / animal_hide_big / animal_trinket / animal_skull`（可连同 `VIET_clutter` 杂物类），保留书籍/武器/甲胄/王权/圣物等有分量的宝物。
2. 或对上述类型提高门槛：仅 `legendary` 且跨宗族者保留（独角兽之角等珍奇仍可留）。
3. **限条数**：宝物志最多输出 N 件（如 20），按（稀有度权重, 流转事件数）排序，防提示词膨胀、模型注意力稀释。

## 问题 6：好友/仇人列传选角 —— 应选真好友/真敌人并附原因

### 根因（两个 bug 叠加，实测复现）

1. **`_select_friend`（biography.py:179–222）与 `_enemy_dates`（225–244）只扫「其他角色」的记忆，且要求 `participants` 值含主角 id**；但 CK3 记忆的 `participants` 只存**对方** id（owner 不在其中），且主角的结友/结仇记忆几乎都挂在**主角自己**名下。实测：富兰克林自己的记忆里有 884/925/930 三次 `became_friends`（participants={'new_relation': 对方}），`_select_friend` 却一个都找不到 → 好友池为空 → 走兜底选中「记忆最多的路人」**萨利姆·鲁斯塔姆**（109 条记忆、与主角零关系，`relation: []`），正文只能靠模型瞎编「遣使通好」。
2. 兜底逻辑（取记忆最多者）与「好友列传应写真好友」的意图冲突；且 `_family_ids` 未排除兄弟姊妹，兄弟可能被选入好友列传。

### 修复

1. **补「主角自身记忆」通道**：`_select_friend` / `_enemy_dates` 同时遍历主角 `rec.memories`，把 `participants` 中的对方 id 计入好友/仇人池（这是 CK3 记忆的权威方向）。
2. **池内规则**：排除家人（妻妾、子女、**兄弟姊妹**——手足之情归家室列传）；在世优先、结友最早优先（沿用现有排序）。
3. **兜底改为「有实质交集者」**：无真好友时，从同朝共事者/宫廷官职/盟友战争等有交集名单中选，并在提示词注明「无结友记录，以同朝共事者X代之」，不再选纯路人。
4. **提示词附「缘由」块**：好友/仇人文章新增【结友缘由】/【结仇缘由】，渲染「X年X月X日，A 与 B 结为好友/结仇」原文事件（正向表述：写明结友/结仇的时间与事件）。

## 问题 7：组装上下文对角色父母「不清楚」

### 根因（父/母 id 在缓存里，但名字渲染错了）

缓存 family 数据正确（实测 16836221 缓存：`family.father=[16820097]`、`family.mother=[45490]`；16820097 缓存：`family.father=[38725]`、`family.mother=[38730]`）。但：
- 父 38725 在孙辈缓存 `culture=None` → name_display 回退 `name_full=菲利普崔佛`（错序）→ 提示词「父：菲利普崔佛」→ 正文「父讳菲利普崔佛」；
- 父 16820097 同样因文化缺失 → 父名制丢失 → 提示词「父：富兰克林·菲利普」（应为 富兰克林·崔佛松，prompts.log:67729）；
- 母 38730（埃兹拉）正常；崔佛·菲利普因自定义出身走「先世：无考」正确。

即：**问题 7 是问题 4 的下游症状**——父母信息本身完整，是姓名渲染在文化缺失时退化成错序/丢父名。

### 修复

1. 依赖问题 4 的统一姓名函数（父名制/名序在文化缺失时按亲属链推断）。
2. `_profile_lines` 的 父/母 行：推断失败时宁缺毋错（不输出错序名）。
3. 可选增强：人物档案给「父：崔佛·菲利普（自定义出身，先世无考）」的显式措辞，防模型再编谱系。
4. 顺带修一处模型误读的实证：富兰克林 935 终传把徐真艳写成「乳母」——她本是崔佛之妾（922 档「妾：徐真艳…」），富兰克林 933 年任她为乳母（宫廷官职数据），提示词两处都有但无关联标注；问题 3 的关系标注机制可一并覆盖这类「父妾→子臣属」的转手。

## 问题 8：为什么会出现「吏部帝国」「枢密院帝国」

### 根因（存档里的朝廷职司帝国级头衔被追加「帝国」层级词）

melt_922 实测存在 9 个帝国级「尚书省六部/御史台/枢密院」头衔：

```
e_minister_of_personnel → 吏部        e_minister_grand_marshal → 枢密院
e_minister_censor → 御史台            e_minister_chancellor → 尚书省
e_minister_of_revenue → 户部          e_minister_of_rites → 礼部
e_minister_of_war → 兵部              e_minister_of_justice → 刑部
e_minister_of_works → 工部
```

这是天朝制（All Under Heaven/天朝 DLC）下中华帝国的**朝廷职司**（六部+两府一台），是官职体系而非诸侯帝国。`facts.title()`（facts.py:449–495）对所有 `e_` 前缀头衔追加政体层级词「帝国」→ 渲染成「吏部帝国 / 枢密院帝国 / 御史台帝国」；`_realm_facts`（朝局风云录，facts.py:2140–2225）把所有 h_/e_/k_ 持有者变化全收，这些职司随之进入「天下大势/朝局动态」文本，模型照抄（第 2 个十年传记出现「御史台帝国、枢密院帝国、六部诸行台如枝蔓盘错」）。游戏内这些职司显示为「X部尚书」类官职，而非「X帝国」。

### 修复

1. **`title()` 对 `key.startswith("e_minister_")` 特判**：不追加层级词；按职司渲染（「吏部」「御史台」），或加「尚书省六部之吏部」式说明；`official_title` 对这类头衔的持有者用「吏部尚书」式官职词而非「吏部皇帝」。
2. **`_realm_facts` 过滤 e_minister_\***：不进「朝局风云录」的高位头衔更替（朝廷职司任免归「宫廷官职/官职任免」），或单列「朝廷职司」小节。
3. **`_primary_group` / 历任 / 直辖** 排除这类头衔进入「之主」序列（玩家亲任时可按官职表述）。
4. 核实「交行台/交皇帝」属正常天朝层级词（行台=d_、皇帝=独立帝国官职词），仅 e_minister_* 特例，不动。
