## 1. 头衔名问题：游戏显示「夏 / 西川 / 东川」，项目写「河西 / 巴 / 蜀」

### 1.1 现象（本次产出中的实例）

- 刺客列传（第1个十年，1179 年事）：**河西宁令嵬名仁孝**。
  游戏当时显示他的头衔为「夏宁令」（k_xia = 夏 + 西夏文化国王词 宁令）。
- 用户另指出：巴/蜀一带头衔游戏显示「西川 / 东川」。

### 1.2 实数据

- 熔件 `title_name_data` 权威：
  - `k_xia`（14640）`name='夏'`，`k_hexi`（14552）`name='河西'`——两个**并列的王国头衔**；
  - `k_xichuan`/`d_xichuan` `name='西川'`；`k_dongchuan`/`d_dongchuan`/`c_dongchuan` `name='东川'`；
  - 改史 `title_history_names`：`k_xingyuan` 867年=兴元 → 1190.1.4=汉（dynn_title_han）→ 1191.3.27=巴（dynn_title_ba）；`k_xichuan` 867年=西川 → 1190.1.4=蜀（dynn_title_shu）→ 1196.11.27=西川（改回）。
  - 项目本地化表 `data/localization.json` 中 `dynn_title_ba=巴`、`dynn_title_shu=蜀`、`k_xia=夏`、`k_xichuan=西川`、`k_dongchuan=东川`——**表本身不旧，改名键也能解析**。
- 嵬名仁孝（48656）1179 年同时持有 k_xia（1139.7.8 起）与 k_hexi（1178.1.1 起）；
  `dead_data.flavor='king_male_tangut'`（本地化=宁令），`death.liege_title=14640`（即 k_xia=夏）。

### 1.3 根因

`facts.py _last_title_place()`（1203 行）为死者官职词补地名时：

1. `official_title()`（1274 行）优先读 `dead_data.flavor`（宁令）→ 只缺地名；
2. `_last_title_place()` 按 `_hold_intervals()` 的**字典迭代顺序**返回第一个同层级头衔——
   k_hexi（tid 14552）先于 k_xia（tid 14640）→ 取到「河西」；
3. 结果拼出「河西宁令」。游戏取的是**首要头衔**（k_xia，更早获得、`domain` 首位、死档 `liege_title` 同指）→「夏宁令」。

即：**同一角色持有两个同级头衔时，地名取错（迭代序 ≠ 首要序）**，属于「默认名 vs 动态名」一类问题的具体 bug。
巴/蜀案例同属此类（改名键 dynn_title_* 已能解析，但需要确保所有渲染路径按「叙事日期」取 `title_name_data`，且 `title()` 与 `_name_at_date()` 口径一致）。

### 1.4 方案

- 修复 `_last_title_place()`：同层级多个头衔时，优先取角色的**首要头衔**（`_primary_title_at` / 死档 `liege_title`）的地名，迭代序仅作兜底 → 嵬名仁孝稳定得「夏宁令」。
- 审计 `title()`（当前名）与 `_name_at_date()`（按日期名）的使用边界：历史语境（历任/朝局/官职）一律走按日期命名，现状语境走当前名；补 `_name_at_date` 的本地化兜底（查不到时回退 `title_name_data.name` 而非裸 key），杜绝 key 泄漏与默认名回退。

## 2. 王祦被写成平民（绸缎商人），动态头衔未生效

### 2.1 现象

第1个十年刺客列传：`1188年十月一日，王祦殁……不过是杭州城一名绸缎商人`。
游戏中王祦是**高丽皇子**（父王晧为高丽皇帝 e_goryeo 持有者）。

### 2.2 实数据

- 王祦（54298）1179–1188 熔件：**无任何领地头衔**（`landed_data` 缺失，`court_data.employer=49934` 即王晧宫廷、knight）；
  其「皇子」身份 = 父王晧（49934）持有 e_goryeo（16980，name=高丽），且王祦位于 e_goryeo 的 `heir` 首位、王晧 `playable_data.diarchy_successor=54298`。
- 项目已有 `prince_title()`（facts.py 1543 行）：**实测对王祦返回「高丽国皇子」**——机制完好。
- 但刺客列传条目（facts.py 4112–4132）只取 `official_title()`（1274 行，对无头衔者返回空），**没有接 `prince_title()` 兜底**；`biography._assassin_kill_lines()`（550 行）同样只用 `office`。

### 2.3 根因

**刺客列传数据流缺「王子/公主称号」兜底**——`prince_title()` 只在人物档案（`_character_profiles` 3396–3402 行）使用，而王祦出现在刺客列传（杀伐名单），该名单只走 `official_title()`。模型拿到「死者：王祦（生于1152年……）」，无任何头衔锚点，遂臆造平民身份（「杭州」来自主角当时驻地标注，「绸缎商人」纯属补职业的幻觉）。

### 2.4 方案

- `killed` 条目（facts.py 4126 附近）：`office = official_title(cid) or prince_title(cid)`（王子称号按**死亡日期**的父头衔计算，避免 as_of 穿越）。
- `_assassin_kill_lines()` 顺带输出「亲缘」已有父名，模型即可把「高丽国皇子王祦」与「父王晧」连起来。
- 同批检查「好友/仇人列传」「妻族」等其它名单型数据是否也需要王子称号兜底（按需）。

## 3. 阉割未被记录：大事记只写「囚禁 → 释放」

### 3.1 现象

1190 年玩家囚禁王晧「穿刺者」并**阉割**（1190.1.19），大事记只写「囚禁 → 施刑 → 获释」，未提阉割；
1192 年贝尔纳德同（模型仅靠「终身无须」猜出「阉刑之创」）。

### 3.2 实数据

- 熔件记忆库：`mem 61331 {type: torturer_memory, participants.victim=49934, date 1190.1.19, variables.data=[{flag:"type", data:{type:"flag", flag:"castrated"}}]}`——**阉割事实在存档里，且带 `castrated` / `castrated_beardless` 标志**（贝尔纳德为 1192.10.12 的 `castrated_beardless`）。
- 游戏本地化：`castrated_desc`=「我在被[X]折磨后成为[阉人]」、`torturer_castrated_desc`=「我的折磨让[受害者]成为[阉人]」、`house_relation_reason_feud_head_castrated`=「被[X]残忍地阉割」。
- 项目现状：
  - `cache_lib.memory_brief()`（486 行）只存变量的 `flag/type/identity`，**把变量的值（`data.flag="castrated"`）丢弃**——缓存里该记忆 `vars=[{flag:"type", type:"flag", identity:null}]`，阉割标志消失；
  - `facts.MEMORY_TEMPLATES`（160–161 行）把两类记忆统一渲染为「{name}施刑于人。」/「{name}受刑。」，且模板不含参与者名（受害者不具名）。

### 3.3 根因

**阉割细节在「记忆提取」与「渲染」两级丢失**：`memory_brief` 丢弃变量值 → 渲染无从区分阉割与普通折磨 → 模型只能写「施刑」；受害者名也未进模板。

### 3.4 方案

- `memory_brief`：对 `data.type=="flag"` 的变量保留 `data.flag` 值（新增字段，如 `value`），旧缓存可不重建（渲染时直接回读熔件记忆亦可，二选一）。
- `_mem_sentence`：`torturer_memory`/`tortured_memory` 遇 `castrated`/`castrated_beardless` 时渲染为「{name}阉割了{other}。」/「{name}被{other}阉割。」（其余折磨维持「施刑/受刑」，并补上受害者名）。
- 家族恩怨史（`house_feuds`）的 `change_reason` 已含「阉割了」游戏文案，`_rerender_feud_event` 天然透传，无需改动。

## 4. 珍宝传板块从未出现

### 4.1 现象

玩家从其他统治者处「偷」了多件高稀宝物（宋御玺、帝国皇冠、圣爱德门之头、拜占庭所罗门王座等），但传记无「宝物志」板块。

### 4.2 实数据

- 玩家名下宝物（熔件 artifacts + `alive_data.inventory`）：aid=138 舍利子、149 帝国皇冠、166 所罗门王座、197 圣爱德门之头、211 宋御玺、16777765 灵便鳞甲……全部 `rarity='illustrious'`（名望级），带 `stolen` 流转史（前主均属他族，跨宗族条件满足）。
- **全档 rarity 分布：common 1208 / famed 112 / masterwork 527 / illustrious 159 / legendary 0**——存档里根本没有「legendary」。
- 游戏定义（`common/` 全量统计）：rarity 只有 common / famed / masterwork / illustrious 四档，**游戏不存在「传奇级」**；游戏概念文本最高档即 卓越级（illustrious）。
- 项目 `facts.ARTIFACT_RARITY = ("legendary",)`（1675 行）只收传奇级 → **永远为空** → `biography.build_articles`（1381 行）`if facts.get("family_artifacts")` 不成立 → 板块不出现。
- 附带：`family_artifacts` 的流转渲染（1733–1747 行）不识别 `stolen` 类型（「偷」的事件被 v14 逻辑略去）。

### 4.3 根因

**稀有度门槛引用了一个游戏里不存在的档位**（v13 定稿时误以为有「传奇级」）；实际最高档为「名望级（illustrious）」。用户口中「传奇级宝物」即游戏最高档宝物。

### 4.4 方案

- `ARTIFACT_RARITY` 改为 `("illustrious",)`（游戏最高档），`rarity_zh` 同步（illustrious → 卓越级/名望级）。
- 流转史补 `stolen` 渲染：`{d}，{actor}窃得`（或「自{actor}夺来」）。
- 保留：狩猎战利品剔除、最多 20 件、跨宗族要求（偷来的宝物天然满足）。
- 注意「宝物志」板块标题与 SECTION_TITLES 的「传家重宝/流转始末」文案按新口径微调。

## 5. 东亚人名昵称格式：`郭靖“欺诈者”` → `欺诈者郭靖`

### 5.1 现象

第2个十年传记：`# 《郭靖“欺诈者”传》`、`《列传·仲宣“秃头”》`；正文 `郭靖“欺诈者”`。
西方人名已是前缀式：`善良者路德维希·路德温格`、`怯懦者迪特里希`。

### 5.2 根因

`facts._insert_nickname()`（682–690 行）：`if "·" in nm: return f"{nick}{nm}"`（西方前缀、去引号）；
**东方名序（姓+名无分隔）与单段名走 `f'{nm}"{nick}"'`（后缀+引号）**——这是 v18（2026-08-31）的旧决策「维持 v17 原设定」，现用户要求对齐西方框架。
第二处：`name_with_regnal()` 的天皇座子女分支（699–704 行）同样输出 `f'{tn}"{nick}"'`。
`htmlview._strip_epithet`（373 行）按「引号后缀」剥绰号，改前缀式后需同步（HTML 目录去绰号分组逻辑）。

### 5.3 方案

- `_insert_nickname`：东方名序分支改为前缀、去引号 → `欺诈者郭靖`、`秃头仲宣`；西方分支不变。
- 天皇座分支同步改为 `{nick}{tn}`（如 欺诈者利永亲王）。
- `htmlview._strip_epithet`/`_person_identity`：前缀式下优先走文件名基名（缓存纯名）匹配，另加「已知绰号词表剥前缀」兜底（或按“姓氏外首 2–3 字为绰号”启发），保证跨十年绰号变化仍能归并同一角色。
- 回归：西方人名（善良者路德维希·路德温格）输出不变；十年传记重跑绰号取自时代末熔件（pipeline v20 `nickname_override`）不变。
