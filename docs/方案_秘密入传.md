## 1. 数据实况（实测）

### 1.1 存档结构

```jsonc
"secrets": {
  "secrets": {                       // 1008 条 (陆氏 878) / 1183 (田所) / 2230 (田所2 901)
    "16777240": {"type": "secret_murder", "target": {"type":"char","identity":43603},
                 "owner": 38682, "participants": [38682]},
    "5": {"type": "secret_lover", "target": {"type":"char","identity":13515},
          "owner": 12286, "participants": [12286], "relation_type": "lover",
          "spent_by": [12675], "cannot_expose": [...]}
  },
  "known_secrets": [                  // 谁知道哪条秘密; 1549–3376 条边
    {"secret": 102, "owner": 38682}, {"secret": 141, "owner": 38684}, ...
  ]
}
```

字段覆盖（三档统计，100% / 部分）：`type`+`target`+`owner`+`participants` 全量；
`relation_type` 301/1181/2221（情人秘密）；`spent_by`+`cannot_expose` 60/81/192（已被使用/封口）；
`variables` 31/53/90。

游戏语义（`_secret_types.info`）：`owner` = 秘密关于谁；`target` = 关联角色（情人/死者/考官…）；
`participants` = 共犯；`known_secrets` = 知情边。

### 1.2 本地化

14–15 种类型，**本地化 100% 覆盖**（`L.loc(table, type)`）：
`谋杀`、`考试舞弊者`、`情人`、`不信者`、`变态`、`孩子的血统`、`秘密信仰`、`挪用国库`、
`贪污犯`、`巫师`、`私通`、`食人`、`血统争议`、`乱伦`、`谋逆`。
`*_desc` 键存在但是模板片段（`'在的考试中作弊'`，占位符被剥掉），**不可直接使用**，需自建句模板。

### 1.3 主角相关（三战役）

| 战役 | 主角持有 | 其中非谋杀 | 外人知情 | 家人/近臣持有 | 主角握他人把柄 |
| --- | --- | --- | --- | --- | --- |
| 陆氏 @878 | 3 | **2**（皆 `考试舞弊者`：涉樊骥、涉李漼） | 0 | **1**（妾灵素 `不信者`） | 0 |
| 田所 @879 | 27 | 0（全谋杀） | 0 | 0 | 0 |
| 田所2 @901 | 64 | **1**（`巫师`） | 0 | 0 | 0 |

**秘密 id 跨档稳定**，可做逐档差分（陆氏实测）：

```
868–871档: 102（考试舞弊者，涉樊骥，即867年乡试）
872档:     +16777240（谋杀叠溪寋，事发871.6.15）
873–878档: +605（考试舞弊者，涉李漼，即872.12.24会试）
879档（死后）: 全部消失
```

即：主角的隐事时间线与他「乡试及第 / 会试及第 / 谋杀」三件事严格对应——
**这是当前传记完全漏掉的一层**（现行输出把科举写成「武人而登文榜…并世罕有其匹」）。

### 1.4 数据缺口（决定了能写什么、不能写什么）

- **存档里没有秘密的日期**（无 creation_date）→ 只能用「跨档差分」得到「自X年档起见于记载」。
- **没有败露信号**：`on_expose` 走事件（`secrets.0001`），这三档的 `character_memory_manager`
  里**没有任何秘密相关记忆类型**（实测 0 条），因此「秘密败露/被敲诈」只能等未来档出现
  （注释里留检测点即可，暂不渲染）。
- `spent_by`（有人已用它做过文章）在主角的 3 条上为 0；`cannot_expose` 同理。
- 「主角握他人把柄」三档皆 0 —— 该维度要先实现，才可能在别的战役里出现。

## 2. 落点选项

| 方案 | 做法 | 成本 | 评价 |
| --- | --- | --- | --- |
| **A（推荐）新篇《阴私录·隐事秘辛》** | 条件生成的第 6–7 篇；档案加一行隐事锚点 | 触发时 +2 次 LLM 调用 | 与「本纪/家室/朝局」并列，叙事最完整；用户倾向的「单开一本列传」 |
| B 并入《本纪》 | 只在主角档案加【隐事】块 | 0 额外调用 | 省，但科举舞弊这种大反转会挤在生平流水里，且家室/朝局的秘密无处安放 |
| C 并入《朝局风云录》 | 秘密当政治把柄写 | 0 额外调用 | 只适合「把柄/敲诈」维度；情人、私生子、不信者这些家内隐事与朝局无关 |

**推荐 A**，并按「有料才开篇」控制成本与噪声：

```
开篇条件 = 主角非谋杀隐事 ≥1  ∨  家人/廷中僚属隐事 ≥1  ∨  主角握他人把柄 ≥1
```
实测：陆氏 **触发**（2 考试舞弊 + 1 妾不信者）；田所 **不触发**（27 条全谋杀、无家人隐事）
→ 不产生额外调用；田所2 触发但内容薄（1 巫师 + 63 谋杀，谋杀另篇承载）。

谋杀类秘密**不在这篇展开**：`secret_murder` 归《刺客列传·刀下诸魂》；
若剧本未生成刺客列传（击杀 ≤5），篇内以一行程序直出的索引带过
（与现有 `MODULE_EXCLUDE` 的「另有谋杀N人，详见《刺客列传》」同法）。

## 3. 方案 A 详细设计

### 3.1 缓存层（`cache_lib.extract_snapshot`，逐档差分，与 `trait_history` 同法）

新增 `cache["secrets_history"]`，**只收与目标集相关的秘密**（owner/target/participant ∈
相关集，或主角 ∈ 知情者）以控体积（三档实测相关秘密 3–27 条）：

```jsonc
{"102": {"type": "secret_exam_cheater",
         "target": 10914, "owner": 38682, "participants": [38682],
         "first_seen": "868.1.1",          // 首档即见 = 数据起点前已有
         "first": true,
         "known_by": [{"id": 38682, "from": "868.1.1", "first": true}]}}
```

- `known_by` 逐档差分：新知情者追加 `{id, from, first}`（首档即有 → `first=true`）。
- 秘密消失（不再出现且主角仍在该档存活）→ 记 `lost_at`（预留，暂不渲染）。
- 相关集用现成的 `_related_ids(f)` 同源逻辑（缓存侧用 `cache["characters"]` 键做过滤，
  与 `characters` 收录口径一致即可）。

### 3.2 事实层（`facts.py`）

新增句模板表（仿 `MEMORY_TEMPLATES`，用游戏类型名兜底）：

| type | 句模板 | 实测样例 |
| --- | --- | --- |
| `secret_exam_cheater` | `{owner}有隐事：科举舞弊（涉及{target}）` | 陆荣廷有隐事：科举舞弊（涉及樊骥） |
| `secret_murder` | `{owner}有隐事：谋害{target}` | （只计数，正文归刺客列传） |
| `secret_lover` | `{owner}有隐事：与{target}私通（{relation_type}）` | |
| `secret_witch` / `secret_deviant` / `secret_non_believer` / `secret_crypto_religionist` | `{owner}有隐事：行巫 / 性僻 / 不信教 / 暗奉异教` | |
| `secret_embezzler` / `secret_siphoned_treasury` | `{owner}有隐事：侵吞库银` | |
| `secret_unmarried_illegitimate_child` / `secret_disputed_heritage` | `{owner}有隐事：血脉存疑（涉及{target}）` | |
| `secret_incest` / `secret_cannibal` / `secret_homosexual` / `secret_coup_plotter` / `secret_murder_attempt` | 乱伦 / 食人 / 断袖 / 谋逆 / 行刺未遂 | |
| 其它 | `{owner}有隐事：{类型名}`（游戏本地化名兜底） | |

新增 `facts["secrets"]` 块：

```python
{"held":[{"line":"陆荣廷有隐事：科举舞弊（涉及樊骥）","since":"","knowers":[]}, …],
 "held_murder":2,                       # 谋杀类计数 (正文交刺客列传)
 "kinsmen":[{"line":"灵素（妾）有隐事：不信教", …}],
 "known":[{"line":"陆荣廷握有X的把柄：…"}],   # 三档为 0, 有则列
 "known_external":[{"line":"亮知悉陆荣廷的隐事：谋害叠溪寋（自872年）"}]}
```

- 日期只写年，首档即见不写（沿用 v24 特质履历的「首见即具不渲染」口径）。
- 「知情者」：除本人外无人 → `至今无人知晓`；有 → `亮、元贞已知情（自872年）`。
- 主角档案加**一行锚点**（共享前缀，供各篇一致）：`隐事：科举舞弊（涉樊骥）；另有谋杀隐事2桩。`
  —— 只在 `held` 非空时出现，避免全篇无谓膨胀。

### 3.3 时间线与模块（`_timeline` + `MODULE_TABLE`）

秘密转成时间线伪事件，**直接复用现有切片/主题机制**：

| 伪事件 type | 文本 | module |
| --- | --- | --- |
| `secret_gained` | `873年，陆荣廷有隐事：科举舞弊（涉及李漼）。` | 隐事秘辛 |
| `secret_known` | `874年，亮知悉陆荣廷的隐事。` | 隐事秘辛 |

- `MODULE_TABLE["隐事秘辛"] = {"secret_gained", "secret_known"}`；
- `MODULE_SLICE`：新篇 `("secrets","lead"/"mid")` 收该模块；
  `("benji","mid")`、`("chaoju","mid")` 也收（隐事本就属生平/朝局大事）；
- 十年戏剧主题自动多出一个候选主题（数据驱动，无需额外代码）。

### 3.4 文章篇目（`biography.py`）

```python
SECTION_TITLES["secrets"] = {"lead": "开篇·阴私之始", "mid": "纪事·隐事秘辛"}
SECTION_REQ["secrets"] = {
  "lead": "写主角身上的隐事：何事、何时见于记载、涉及何人、有谁知情；以资料为限。",
  "mid":  "写家人与近臣的隐事、把柄的流转与知情者的浮沉；以资料为限。",
}
```

- `build_articles`：按 §2 的触发条件追加
  `{"key":"secrets","title":"阴私录·隐事秘辛","subject":None,...}`；
  位置放在《朝局风云录》之前（人物 → 家室 → 隐事 → 朝局）。
- `_article_facts(facts, cache, "secrets", section)`：
  开篇给「主角隐事 + 知情者」，纪事给「家人/近臣隐事 + 把柄 + 时间线切片」。
- 与《刺客列传》互斥处理：有刺客列传时 `held_murder` 只写计数 + 索引行。

### 3.5 提示词规则

`LANGUAGE_FLAVOR_RULE` 已有「照资料写明的情形落笔」的同款写法，新增：

```
「隐事笔法」: 隐事一律按其记载形态书写——无人知情者写「其事隐密，时人未觉」；
已知情者写「某已知情」，并写出其人身份与此后往来。
```

（正向表述：只给「怎么写」，不给「不要写」。）

### 3.6 验证（`experiments/verify_secrets.py`）

- 缓存：`secrets_history` 首见档与实测一致（陆氏 102=868首档、16777240=872、605=873）；
- facts：`held` 2 条（皆科举舞弊）、`kinsmen` 1 条（灵素不信者）、档案锚点存在；
- 时间线：`873年…隐事：科举舞弊…` 存在且 module=隐事秘辛；
- 篇目：陆氏触发《阴私录》，田所不触发（避免无谓调用）；
- 兜底词扫描为 0；提示词字符增量 < 1.2k（对齐 v27 瘦身指标）。

## 4. 成本与风险

| 项 | 估计 |
| --- | --- |
| 代码量 | 缓存 ~40 行、facts ~120 行、biography ~60 行、验证 ~120 行 |
| 提示词增量 | 触发时 +1 篇（lead+mid），共享前缀 +1 行；田所类战役 **0 增量** |
| 缓存增量 | `secrets_history` 只收相关秘密（3–27 条/战役，<10KB） |
| 风险 1 | 首档即见的秘密没有「何时发生」→ 一律不写日期，避免编造（沿用特质口径） |
| 风险 2 | 秘密消失语义不明（败露 or 失效 or 主角身故）→ 只在主角仍存活时记 `lost_at`，暂不渲染 |
| 风险 3 | 谋杀秘密与刺客列传重复 → 已按「只计数 + 索引」隔离 |
| 风险 4 | 现存 3 档之外可能出现「主角掌他人把柄」大量条目 → 渲染上限（如 8 条 + 「等N人」） |

## 5. 需要用户拍板

1. **方案选择**：A 新篇《阴私录》（推荐）／B 并入本纪／C 并入朝局？
2. **篇名**：《阴私录·隐事秘辛》 还是 《秘辛录·隐事》 或其它？
3. **是否把隐事写进本纪/朝局的年表切片**（`MODULE_SLICE` 加两处）？
   —— 加了会让「科举舞弊」在生平叙述里也出现（更一致），不加则只在《阴私录》里揭底（更有反转感）。
4. **谋杀秘密**：只计数 + 索引（推荐），还是也在《阴私录》里逐人点名？
5. **触发门槛**：非谋杀隐事 ≥1 即开篇（推荐），还是要求 ≥2 / 或只要有任何隐事？
