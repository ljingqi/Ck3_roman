## 问题 1：恩怨史泄漏 `TOOLTIP:LANDED_TITLE,13449 L; 尾张国的任命`

### 1.1 现象

prompts.log 多处出现（第 3/4 个十年、终传、家族恩怨录各请求）：

```
895年7月30日，备后伯爵大和行有与足利男爵麦克·汤利竞争TOOLTIP:LANDED_TITLE,13449 L; 尾张国的任命
907年3月18日，日本皇帝麦克·汤利从大和惟条手中剥夺了TOOLTIP:LANDED_TITLE,12946 L; 出羽地方
```

最终 .md 里模型自行擦掉了 TOOLTIP（没泄漏到正文），但**提示词里裸键值出现，违背「干净事实铁律」**，且 52 处同类泄漏。

### 1.2 根因（已复现）

游戏 change_reason 原文（melt_897 `house_relations` 实测）：

```
…竞争\x15ONCLICK:TITLE,13449 \x15TOOLTIP:LANDED_TITLE,13449 \x15L; 尾张国\x15!\x15!\x15!的任命
```

`facts.py:_clean_ck3_loc`（2173–2187）的剥离正则：

```python
s = re.sub(r"ONCLICK:[A-Z]+,\d+\s*", "", s)   # 行 2179
s = re.sub(r"TOOLTIP:[A-Z]+,\d+\s*", "", s)   # 行 2180
s = re.sub(r"L(?=\s)", "", s)                 # 行 2181
```

三个漏洞（已用真实字符串逐一验证）：

1. **`[A-Z]+` 不匹配下划线**：`LANDED_TITLE` 中 `_` 不在 `[A-Z]`，`[A-Z]+` 只吃到 `LANDED`，遇到 `_` 即失败 → `TOOLTIP:LANDED_TITLE,13449` 原样残留（`CHARACTER`/`TITLE` 无下划线故能剥掉，所以只漏 TOOLTIP）。
2. **链接标记 `L` 后跟 `;` 时剥不掉**：`L(?=\s)` 只处理 `L `（后随空格），`L; 尾张国` 里 `L` 后是分号 → `L;` 残留。
3. 剥离顺序 ONCLICK→TOOLTIP 本身没问题，但 1+2 叠加即得泄漏原文。

### 1.3 修复（`_clean_ck3_loc`，一处改动覆盖全部路径）

```python
# v17: 头衔链接块整体剥离 (ONCLICK:TITLE,id TOOLTIP:LANDED_TITLE,id L; 名称)
s = re.sub(r"ONCLICK:TITLE,\d+\s*TOOLTIP:[A-Z_]+,\d+\s*L[; ]?", "", s)
s = re.sub(r"ONCLICK:[A-Z_]+,\d+\s*", "", s)
s = re.sub(r"TOOLTIP:[A-Z_]+,\d+\s*", "", s)
s = re.sub(r"L(?=[;\s])", "", s)      # 孤立 L 链接标记 (后随 ; 或空格)
s = re.sub(r"; ", "", s)              # L; 残留的分号分隔
```

验证（真实原文跑修复后逻辑）：`亲王行有与当主麦克竞争 尾张国的任命` → 经既有汉字间距清理 → `竞争尾张国的任命`，干净。`_rerender_feud_event`（1194–1206）与 `_clean_ck3_loc` 直调路径（1201/1206）同受此修复。

## 问题 2：日本帝国之主被渲染成「日本皇帝」——应为「日本关白」

### 2.1 现象


  且游戏自己的 change_reason 原文就写「\x15high 关白\x15!时康」——**程序重渲染反而改错了**。

### 2.3 修复（`_office_word` 加日式政体分支，按游戏本地化键）

## 问题 4：【主角大事摘要】行数太多，模型看不过来

### 4.1 现状量化（第 3 个十年 prompt 实测）

- 【主角大事摘要】**89 行**，覆盖 867–897 全部 31 年（prompts.log 21516–21604）；
- 其中谋杀行 50+，且逐年逐条平铺（886 年萨法尔五子一行一人）；
- 好友《列传·穆纽》的「相关年表」又把同一份时间线**整份再列一遍**（21622 起，因过滤条件是「含主角名或传主名」的并集，穆纽行迹少 → 命中几乎全部主角事件）；
- 终传【概览】错标「本十年谋杀69次」（应为「一生」，as_of 被设成死亡日所致，见 4.4）。

### 4.2 根因

- `biography.py:_shared_facts_block`（869–878）：摘要 = 时间线里含主角名的全部事件原文，逐字节进**每个**请求（总纲 + 5~9 篇 × 2 板块，约 16 次调用共享）；
- 既有的压缩（`_merge_same_day_events` / `_merge_same_month_events`）只到**月**粒度，且不合并谋杀/添丁等「人名型」事件；
- D:\Journal 的对照：`magazine.py` 每篇文章只 `render_facts(article_key, section_key)` 取**本篇所需**数据 + 短导言，从不把全量年表塞进每个请求——我们共享前缀里这 89 行就是「多传」的典型。

### 4.3 修复方案（程序聚合，模型只收结果）

新增 `facts.py:_year_summary(f)`（结构化聚合，非正则改文本），产出按年一行：

```
【主角大事摘要】
867年，埃德吉富、埃尔弗莱德先后与麦克·汤利结怨。
869年，与吉塞勒·加洛林私通相恋；得长子崔西·麦克斯多蒂尔。
871年，谋杀里瓦朗·马布·萨洛蒙。
872年，与阿尔东萨·拉米鲁斯私通相恋；谋杀努妮娅·阿方苏斯。
874年，与萨洛蒙·马布·里瓦朗结仇；添子汤米·麦克松、塔妮莎·韦尔赫·麦克。
875年，谋杀萨洛蒙·马布·里瓦朗；与吉塞勒·加洛林成婚；添子丹尼斯·麦克斯多蒂尔。
886年，谋杀阿姆鲁·萨法尔、穆罕默德·萨法尔、瓦哈卜·萨法尔等5人。
890年，谋杀白敬忠、白敬立、白知微等8人。
…
```

- **按年聚合**：同一年同型事件并一行——谋杀/添丁/结怨/结仇/结友等「人名型」合并（人名 ≤3 全列 + 等N人，沿用 `_agg_line` 计数法）；成婚/登位/亡故/囚禁/战争等关键事件保留动词原句但去月日；
- **十年窗口（源头窗口化）**：`_timeline`（facts.py:2440–2444）在 `f.decade` 时加下界 `(as_of 年−10).1.1`（首十年下界取缓存起始年）——摘要、本纪年表、概览统计、戏剧主题、朝局动态等一切以 timeline 为源的数据随之只含本十年；戏剧性事件（villain_chains 自管 `in_span`）保持全期作「人生背景」；
- **去出生年**：聚合行一律不带 `（X年生）`（与问题 3 同向）；
- **相关年表按传主名过滤**：friend/enemy 的 `_timeline_texts` 过滤名单由 `[主角,传主]`（并集，穆纽类传主整份复述主角年表）改为**只按传主名**（biography.py:626 改 `names=[subj_name]`）——只留传主自己的记忆与传主↔主角的交集事件；主角大事件由共享前缀的摘要承载；
- 本纪的【大事年表】仍给**全量带日期**时间线（纪传体需要精确日期），十年传记是否也窗口化见第六节决策点 2。

### 4.4 顺带修复：终传标签错标「本十年」

`_bio_as_of`（pipeline.py:661–667）对终传也返回死亡日 → `facts["as_of"]` 恒真 → `_shared_facts_block`（865–868）与 `_decade_theme_note`（828–839）把终传的概览/主题写成「本十年」。
修复：以显式 `facts["decade"]`（新字段，见问题 5）判定「本十年」vs「一生」，不再用 `as_of` 有无。

## 问题 5：刺客列传十年小传里包含前面所有谋杀事件

### 5.1 现象（output/汤利 实测）

- 第 2 个十年（878–888）传记的《刺客列传·纪事·诸魂行迹》：
  **里瓦朗(871)、努妮娅(872)、萨洛蒙(875)、阿达尔贝托(877)、巴西尔(878)…** 全是第 1 个十年已写过的人；
- 第 4 个十年（898–908）传记的「纪事·上」同样从 871 年最早的死者讲起；
- 每个十年都把**此前全部谋杀**重新小传一遍——十年小传名不副实，且模型注意力被旧账占满。

### 5.2 根因

`facts.py:_killed_by_player`（3705–3795）：as_of 截断只做上界

```python
if f.as_of:
    out = [e for e in out if e["death_date"] == "9999.9.9"
           or cl.date_key(e["death_date"]) <= ao]        # 只砍未来，不砍过去
```

十年传记的 as_of = 十年末（pipeline.py `_decade_cutoff` 645–658），于是每篇十年传都收录**建档以来全部死者**，切片（`_assassin_sections` 1264–1282）按死亡先后等分，最早的死者永远进「纪事·上」。

### 5.3 修复（十年窗口下界）

- `build_facts` 新增 `decade` 参数 → `facts["decade"]`（`generate_biography` 已有 decade 变量，直传）；
- `_killed_by_player`：当 `f.decade` 时，死者下界 = `(as_of 年 − 10).1.1`（首十年下界取缓存起始年，防窗口早于建档）；
- 文章收录条件 `len(killed) > 5` 随之按窗口生效——十年内杀 ≤5 人则该十年不生成刺客列传（合理：十年聚焦）；
- 终传/在世（无 decade）不收下界，仍全期。

## 问题 6（用户补充）：动态国名失效——「关内王王言」游戏里显示「秦王王言」

### 6.1 现象

刺客列传死者行（第 4 个十年/终传各请求）：

```
死者：关内王王言（生于847年1月1日，殁于891年6月3日，被麦克·汤利秘密谋杀。）
```

用户在游戏里看到的是「秦王王言」。

### 6.2 根因（已定位到 `_last_title_place` 取「获得日」名）

数据（melt_910 实测）：

```
k_guannei (14438) title_name_data.name = 秦
title_history_names: 867.1.1→k_guannei(关内), 889.1.30→dynn_title_di(翟), 891.6.27→dynn_title_qin(秦)
死者 王言 (15285): 847.1.1生, 891.6.3殁, dead_data.flavor=king_male_chinese(王)
  持有 k_guannei: 886.9.19–891.6.3   ← 上任时国号还是「关内」
其子 王思恭 (60998): 889.11.28生, 891.6.25殁, 持有 891.6.3–891.6.25  ← 上任时已改名「翟」
```

`official_title` 对死者走 dead_data.flavor 路径（facts.py:1124–1131）：官职词「王」+ `_last_title_place`（1044–1111）补地名。
而 `_last_title_place` 取 `self._name_at_date(tid, gain)`（行 1068）——**名字取「持有开始日」**：
王言 886.9.19 上任 → 国号「关内」→ 关内王；王思恭 891.6.3 上任 → 国号「翟」→ 翟王。
游戏角色窗显示的是**当前国号**（秦，891.6.27 起），程序却用几十年前的上任名——动态国名失效。

（对比：恩怨史 `_feud_role_title` 按**事件日期**取国号（903 粤、更早桂）是对的——活人按事时点；
死者官职应取**当前/as_of 时点**国号，与游戏角色窗一致。）

### 6.3 修复（`_last_title_place` 地名改取当前名）

行 1068 `nm = self._name_at_date(tid, gain)` → `nm = self._name_at_date(tid, self.as_of) or self.title_base_name(tid)`
（as_of 为空时回退基础名 = 当前国号）。dead_data.domain 兜底分支（1082–1110，县邑级）不动。
验证：`official_title(15285)` 应得「秦王」（王言）、`official_title(60998)` 应得「秦王」（王思恭）。

## 问题 7（用户补充）：世系编号（II/III 二世标记）程序读不到

### 7.1 现象

游戏里同一头衔的同名统治者显示「奇普里安II」「鲁斯兰·克里维奇II」等世系编号，
程序只渲染静态名（两个鲁斯兰·克里维奇无法区分，模型曾把父子写成「两王同死」）。

### 7.2 根因（编号不存存档，游戏动态计算）

- 熔件 `first_name` 只有 `Ciprian`/`Ruslan`，**无任何编号字段**（已核对 16801277 全字段）；
- 游戏显示时按「该角色**首要头衔**的 title history 中**同名前任数 + 1**」动态算出
  （两次独立实证）：
  - c_braila：852 Boris → 860 **Ciprian** → 889 Basarab → 893 **Ciprian** → 后者 = II；
  - k_ruthenia：881.3.14 **Ruslan**(父843生) → 881.9.15 **Ruslan**(子873生) → 子 = II。
- 程序用熔件静态名，自然读不到动态编号；且恩怨史重渲染会丢弃游戏原文里已带的「II」。

### 7.3 修复（`Facts` 新增三件 + 六处应用）

- `regnal_number(cid, tid, date)`：数 title history 中登位（或 date）前同名前任 +1
  （同名按熔件 raw `first_name` 比对，中文 mod 名同码点串一致）；
- `name_with_regnal(cid, date)`：显示名 + 编号，≥2 追加中文世系
  （`_ordinal_zh`：二世…九世带「世」，**十起不带**——路易十一/路易十四）；

  刺客列传死者行、人物档案名、主角名/概览统计（与时间线同口径，按名过滤不破）；

## 问题 8（用户补充）：世系编号位置 + 昵称读取

### 8.1 世系编号位置（v17 结论：游戏在末尾；**v18 用户决策：改按史书惯例紧跟名**）

游戏中文姓名模板 `character_l_simp_chinese.yml`：

```
REGNAL_NAME_ONE_NAME:       "$NAME$$NUMBER$"                        → 奇普里安II（恩怨史短名）
REGNAL_NAME_MULTIPLE_NAMES: "$FIRST_NAME$·$REMAINING_NAME$$NUMBER$" → 鲁斯兰·克里维奇二世
```

游戏自己的编号在完整名字末尾（「鲁斯兰·克里维奇二世」），v17 据此实现（本地化表里手写的
「尼基弗鲁斯二世·福卡斯」「安德罗尼科斯二世·巴列奥略」是书签/人物简介文案，不是姓名模板）。
**v18（2026-08-31）用户决策：改按史书惯例——编号紧跟名、家名/父名在后**
（鲁斯兰二世·克里维奇、洛泰尔二世·加洛林），不再把编号缀在姓上；
且**仅西方名序（名·家名）标编号，东方人名（姓+名，无分隔）与单段名一律不标**。

### 8.2 昵称（结论：可读，已实施）

- **数据**：熔件角色 `nickname_text` 直接就是中文昵称（勇敢者/铁腕/颤抖者…，本档数百人），
  程序此前完全没读（grep 零命中）；
- **游戏中文模板**（昵称插在名之后、家名/父名之前，中文双引号）：
  `CHARACTER_FIRST_NAME_NICKNAMED_PATRONYM: "$NAME$“$NICK$”·$PATRONYM$"` → 名“昵称”·家名；
  东方 `CHARACTER_FIRST_NAME_NICKNAMED_DYNASTY_ALWAYS_FIRST: "$DYNASTY$$NAME$“$NICK$”"` →
  姓+名“昵称”；另有前缀变体（少数文化）；
- **实施**：`Facts.nickname(cid)` 读 `nickname_text`，`_insert_nickname` 按名序插入
  （含 `·` 的西方名 → 名“昵称”·家名；东方/单段名 → 末尾追加），并入 `name_with_regnal`
  同口径六处渲染点；（v18 起见 8.3：绰号前置去引号、有绰号不再标编号）
- 验证（experiments/verify_v17_nickname.py）：时间线/刺客列传/档案 33 处带昵称；
  重跑全篇后《列传·萨洛蒙“外来者”·马布·里瓦朗》、查理“秃头”·加洛林、
  大和惟条“秃头”等全部正确。

### 8.3 (v18, 2026-08-31 用户决策)：有绰号 → 绰号取代世系编号

- **组合模板的缺失**：游戏对「既有绰号又有编号」的角色走昵称模板，编号并进名 token、
  绰号跟在后面（`CHARACTER_TITLED_FIRST_NAME_NICKNAMED: "$TIER$$NAME$"$NICK$""` →
  游戏显示「意大利国王路易二世"青年"」）；v17 实现把昵称模板与编号模板**拼接**成
  `名"昵称"·家名二世`（路易"青年"·加洛林二世），是游戏从不显示的形式。
- **用户决策**：西方名序 绰号前置、去引号（秃头查理·加洛林 / 青年路易·加洛林 /
  征服者威廉·诺曼底，中文史传惯例），**有绰号即不再标「二世」**（编号让位于绰号）；
  东方名序维持 姓+名"绰号"（大和惟条"秃头"）。
- **代码**：`_insert_nickname` 西方分支改 `f"{nick}{nm}"`（去引号前缀）、东方分支不变；
  `name_with_regnal` 有绰号直接返回绰号形式，跳过 `regnal_number` 计算与追加；
  无绰号路径：编号紧跟名、家名在后（鲁斯兰二世·克里维奇），东方/单段名无编号（见 8.1）。
