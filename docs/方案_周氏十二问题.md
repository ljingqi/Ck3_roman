### 1.1 问题 1：`MAX_RECURSIVE_DEPTH` 的来源

`melt_888_01_01.json` 中 `house_relations.database` 的 914 号关系（houses `[6190, 12128]`，
即周氏 × 程氏）:

```
history[0]: date 882.3.30, change_reason "\x15ONCLICK:CHARACTER,38673 …\x15high 乡绅\x15!，\
             \x15high 周\x15！\x15high 立齐\x15!…谋杀了…程士庸"     ← 可读，渲染成「882年3月30日…」
history[1]: date 882.4.8,  change_reason "MAX_RECURSIVE_DEPTH"    ← 全档 1 处，无中文
```

- 该串不是项目代码产物，是 rakaly 熔出时对**超深嵌套本地化**留下的哨兵串；`facts.house_feuds`
  经 `_rerender_feud_event` → `_clean_ck3_loc` 原样透传，于是进了提示词，模型照抄成
  「卷宗有阙文，以『MAX_RECURSIVE_DEPTH』标记存疑」。
- 同日的真实史事在缓存里**完整可读**：

```
38673 周立齐  became_rivals           882.4.8 {'rival': 11772}
11772 程岩    became_rivals           882.4.8 {'rival': 38673}
11772 程岩    house_feud_started_memory 882.4.8 {'house_head': 38673, 'attacker': 38673,
                                                'victim': 10438}  vars: house_feud_reason=family_killed
```

→ 可程序重建为「周立齐谋杀程士庸，程氏因族人被杀与周氏结为世仇」类句，不必依赖游戏原文。

### 1.9 问题 12：Mod 本地化为何没生效

- `localization.enabled_mod_dirs` 本身是对的：读活动 playset（`launcher-v2.sqlite`，
  当前 `默认mod` 7 个启用 Mod，`dirPath` 落在 `F:\SteamLibrary\steamapps\workshop\content\1158310\*`）。
- 但 `load_localization_table`：

```python
if not force and os.path.isfile(path):        # ← 只看文件在不在
    return data.get("table") or {}            # ← 永不判「启用 Mod 变了」
```

`data/localization.json` 时间戳 2026/8/30，而 `deviants_mask_mod` 在活动 playset 里是
**未启用**（`enabled=0`）；实测其 12081 个中文键（`trait_deviants_blackmailvictim`=勒索受害者…）
一个都不在表里。用户一旦勾选该 Mod，模型看到的就是键值（或整条事实被跳过）。
- 另有两处覆盖缺口：Mod 常用的 `localization/replace/<lang>/` 目录未被遍历；
  本地化未命中的键没有审计出口（无从知道缺什么）。

## 2. 逐项方案

### 问题 1：恩怨史键值泄露（程序重建 + 全局面兜底）

1. **判不可读**：新增 `facts._loc_text_ok(s)`——去格式码后必须含中日韩字符，
   且不含形如 `^[A-Z][A-Z0-9_]{2,}$` 的纯大写哨兵串；否则视为不可读。
   `_clean_ck3_loc` 末尾接一层清洗：命中则返回 `""`。
2. **程序重建**：`Facts._feud_event_fallback(house_ids, date)`——在 `self.cache["characters"]`
   中按日期检索与两家族相关的记忆，优先级：
   `house_feud_started_memory`（用 `house_feud_reason` → 中文原委）/`house_feud_ended_memory`/
   `became_rivals|became_grudge|became_nemesis`/`successful_murder`（`victim` 是本族成员时）。
   渲染例（882.4.8）：`周立齐谋杀程士庸，程氏由是结为世仇。`
3. **全事实面兜底**：新增 `facts.sanitize_fact_text(s)`，按行剔除含裸键的行
   （命中的行记入 `logs/journal.log`，附块名与原文，便于回溯）；
   在 `biography._render_block` 与 `_shared_facts_block` 的出口各调一次，
   覆盖 `house_motto`、`nickname_text`、`death reason`、`change_reason` 等所有原文透传口。
4. 保留原有正向表述纪律：提示词不出现「不要写键值」之类句子，靠程序保证。

### 问题 2：【主角处境】只记冒险者时期驻地

1. 新增 `Facts.camp_intervals(cid)`：由 `_hold_intervals(cid)` 取 `title_kind(tid) == "camp"`
   的区间 `[(gain, loss|None)]`。
2. `_protagonist_stations` 改为：
   - 阶段行：只保留营地区间（`{date}任{统治者称呼}（无地冒险者营地）`）；
   - 驻地行：`player_locations` 中**日期落在营地区间内**者；
   - 无营地区间 → 返回 `[]` → `_shared_facts_block` 不下发该块（同 v28b 空块纪律）。
3. 块名建议改【冒险者行踪】（语义即「游侠时期驻地」），一并避免「处境」被读成定居治所。
   → **待确认 D4**。
4. 周立齐档预期：该块整体消失（他的 14 行现状全是定居期/旅行点）；
   无地冒险者档（如 `output/田所2` 的营地期角色）保留营地期的「驻X」行。

### 问题 3：财务信息全部档位化

1. `localization.py` 增 `build_currency_levels(cfg)` → `data/currency_levels.json`：
   从游戏 + 启用 Mod 的 `common/defines/00_defines.txt` 取
   `LEVELS_PIETY/PRESTIGE/INFLUENCE/MERIT` 与 `DEFAULT_*_LEVEL_CAP`；
