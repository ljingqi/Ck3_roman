## 1. 世族（家族庄园）被写成「无地冒险者营地」

### 1.1 证据

存档实测（`experiments/diag_lushi.py`）：

```
玩家 38682 landed: government=celestial_government, domicile_type=east_asian_estate,
                   domain=[14473 商州, 18114 陆家族, 14474 上洛县]
18114 = x_nf_552「陆家族」  ← 家族庄园头衔
domiciles.database 437 = {domicile_type: east_asian_estate, owner_title: 18114, herd: 0, provisions: 0}
游戏自身称呼：meta_player_name = "乡绅，陆荣廷"
```

提示词原文（`logs/prompts.log` 42410 附近）：

```
政体天朝制，867年起执掌一方，直辖3地：商州、陆家族、上洛县……
历任867年任陆家族之主（无地冒险者营地）。
```

### 1.2 根因

- `facts.py:4456`：`if (ptid is not None and pkey.startswith("x_")) or gov == "landless_adventurer_government":`
  玩家首要头衔是 `x_nf_552`（家族庄园），`x_` 前缀命中 → 走「无地冒险者营地」分支。
- `facts.py:1275-1302`：`held_titles` 对一切 `x_` 头衔取「营地宗旨词」（`_camp_holder_word`），
  取不到就回退「X之主」，并在 `facts.py:1298-1302` 追加 `（无地冒险者营地）`。
- 同类 `x_` 头衔实测（`melt_878`，共 1255 个）**语义分四类**：
  | 前缀 | 数量 | 含义 |
  | --- | --- | --- |
  | `x_c_nomad_*` | 379 | 游牧毡帐（已有专判 `_is_nomad_camp`） |
  | `x_mc_*` | 654 | 雇佣兵团 |
  | `x_nf_*` | 116 | **世族/家族庄园（本次病灶）** |
  | `x_d_laamp_*` | 36 | 无地冒险者营地（田所战役即此，`x_d_laamp_552`） |
  | `x_script_*` / `x_ho_*` | 70 | 脚本头衔 / 骑士团 |

### 1.3 方案

新增 `Facts.title_kind(tid)`（键前缀 + 政体联合判定，单一出口）：

| 判定 | 结果 |
| --- | --- |
| `landless_adventurer_government` 或键含 `_laamp_` 或 `x_mc_`/`x_script_`/`x_ho_` | `camp`（营地） |
| 键含 `_nf_`（`x_nf_`/`c_nf_`/`d_nf_`）或 `domicile_type in {east_asian_estate, japanese_manor, estate}` | `estate`（世族庄园） |
| 键 `x_c_nomad_*` | `nomad`（毡帐，沿用现判） |
| 其余 | `landed`（领地） |

落地四处：

1. `_protagonist`（`facts.py:4453-4503`）：`landless` 分支只在 `camp` 时进入；
   新增 `estate` 分支 → `p["estate"]=True`、`p["estate_name"]="陆家族"`、
   `p["estate_holder"]="乡绅"`（`_estate_holder_word` 已有，`facts.py:1999-2011`）、
   `p["domicile"]="世族庄园"`。
2. `held_titles`（`facts.py:1275-1284`）：`estate` 阶段写「**陆家族乡绅（世族庄园）**」；
   `（无地冒险者营地）` 标注只在 `camp` 时追加。
3. `biography._profile_lines`（`biography.py:607-652`）：新增世族句
   「867年起为陆氏世族庄园「陆家族」之主（乡绅）。」；`营中/廷中僚属` 判定
   （`biography.py:659-664`、`biography.py:987`）沿用 `p["landless"]`，世族自动走「廷中」。
4. 本纪取料要求（`biography.py:118`）：「执掌领地或经营营地」→ 增补「世族庄园」一档。

**称谓取值（请用户拍板）**：默认用**游戏本地化原词**「乡绅」（`celestial_estate_holder_male`），
与存档 `meta_player_name` 一致；备选「世族庄园之主」。

## 2. 天朝制官职变迁被读成「被打败又夺地」

### 2.1 证据

玩家头衔记忆（缓存 `player_38682.json`）：

```
867.1.2  ascended_throne_memory reason=created              title=18114 陆家族
869.1.25 ascended_throne_memory reason=appointment_succession title=14542 阶州
872.1.4  lost_title_memory     reason=stepped_down           title=14542 阶州
875.7.18 ascended_throne_memory reason=appointment_succession title=14473 商州
```

提示词原文：

```
867年1月2日，陆荣廷登位，得陆家族。
869年1月25日，陆荣廷登位，得阶州。
872年1月4日，陆荣廷让出阶州。
872年1月4日，杨玄价登位，得阶州。
875年7月18日，陆荣廷登位，得商州。
本十年戏剧主题: …起家发迹…失位让土…
```

全档 reason 分布（5 份缓存统计）：` ascended: revoked 1215 / appointment_succession 1183 / inheritance 814 /
granted 494 / migration 476 / created 451 / appointment 338 / conquest* 302…`；
`lost: migration 412 / revoked 251 / conquest 231 / stepped_down 221 / granted 34 / appointment 19…`

### 2.2 根因

1. `facts.py:156-157` 记忆模板与政体无关：`{name}登位，得{title}` / `{name}让出{title}`。
   天朝制的「任命/调任」与封建制的「登位/失土」共用同一句话。
2. `facts.py:3611-3612` 戏剧模块名 `起家发迹`/`失位让土` 直接进提示词的主题行。
3. `facts.py:1312` 历任阶段失去头衔一律写「让出」。
4. `biography.py:118/138` 板块要求写「登位与失土时刻」「让土」。

### 2.3 方案

**(a) 记忆句按「政体 × reason」出动词**（新增 `Facts.title_event_verb(tid, reason, gain=True)`）：

| reason | 天朝制/行政制（`_CELESTIAL_LIKE_GOVS`，`facts.py:1397`） | 其余政体（默认保持现状） |
| --- | --- | --- |
| `created` | 受封/起家 | 登位，得 |
| `appointment*` | **受任** | 受任 |
| `inheritance` | 承袭 | 承袭 |
| `granted` | 受封 | 受封 |
| `conquest*` | 攻取 | 攻取 |
| `revoked`/`usurped` | 夺得 | 夺得 |

失去侧：`stepped_down` → 天朝制「**卸任**」（其余政体保留「让出」）；`appointment` → 「调任」；
`revoked` → 「被褫夺」；`conquest*` → 「失守」；`granted` → 「转授」；`destroyed` → 「毁弃」。

落地：`facts.py:3536-3546`（`_mem_sentence` 的 `TITLE_VAR_TYPES` 分支）取 `self._title_government(tid)`
与 `vars.reason` 后出句；`facts.py:1312` 同源换词。

改后预期：`869年1月25日，陆荣廷受任阶州。` / `872年1月4日，陆荣廷卸任阶州。` /
`875年7月18日，陆荣廷受任商州。`

**(b) 戏剧主题显示名按政体换词**（不动内部键，避免破坏 `MODULE_SLICE` 切片）：
`biography._decade_theme_note`（`biography.py:1123-1134`）加一层显示映射
`起家发迹 → 受任迁转`、`失位让土 → 卸任调转`（仅天朝制/行政制）。

**(c) 板块要求换词**：`biography.build_articles.mk_sections`（`biography.py:1635-1645`）
对天朝制主角做一次词面替换（「登位」→「受任」、「失土/让土」→「卸任/调任」、「战争与囚狱转折」保留）。

## 3. 藤原利仁「莫名其妙成了关内经略使」

### 3.1 证据（**这是本次最严重的正确性 bug**）

```
关内路 k_guannei(14438) 现任持有者 = 16293
熔件 melt_878 角色 16293: first_name="Liangshi_826F_58EB", culture=47(汉), faith=48(经学), dynasty_house=10015(郑)
→ 正确的名字是「郑良士」（826F=良, 58EB=士；宗族=郑）
cache_lib.display_name(16293) 实际返回 = 「藤原利仁」
```

`data/names.json`：

```
schema/source: source = "1074.1.14"     ← 这张表来自**另一场战役**的存档
names["16293"] = {first_name:"Toshihito", name_zh:"利仁", house_name:"鱼名流", dynasty_name:"藤原"}
```

实测：陆氏熔件里 **27662 / 50261** 个角色的自身名字与 `names.json` 同名 id 记录**不一致**
（角色 id 只在同一存档内有意义；`build_names.py:51` 取的是「所有战役文件夹里日期最新的 melt」）。
其中进入提示词的人：`realm_history` 103 名持有人中 1 名（16332 科泽尔→努拉），
上位链 1 名（16293 郑良士→藤原利仁）——就是问题 3。

### 3.2 根因

`cache_lib.display_name`（`cache_lib.py:936-956`）顺序为：
**缓存 → `names.json`（跨战役、按 id）→ 熔件角色解码**。
熔件里明明有该角色（`name_zh` 可解码为「良士」），却被 `names.json` 抢先返回错名。

### 3.3 方案

1. `display_name` 取值顺序改为：**缓存 → 熔件角色（`chars[cid]`，含 `name_zh`/`house_name`/`dynasty_name`）→ `names.json` 兜底**；
   即只有「熔件里根本没有这个角色」时才查 `names.json`。
2. `names.json` 增加 `playthrough_id` 字段并在 `_load_names` 侧校验：战役不同则**整表不用**（`build_names.py` 写入 `playthrough_id`）。
3. README「用法」补一句：`build_names.py` 应针对**当前战役**执行（避免再出现跨战役污染）。

**影响面**：`display_name` 是全项目唯一姓名出口（`facts.name_or`/`name_with_regnal` 等），
改后陆氏提示词里 `关内路（藤原利仁）` → `关内路（郑良士）`。这是修正，不是回归。

## 4. 天朝制下显示「牧群0」

### 4.1 证据

提示词：`政体天朝制，…，封臣2人，牧群0，御前会议六席。`
各战役缓存 `landed.herd/provisions/domicile_type`：

```
田所   landless_adventurer_government  herd=0        provisions=2175.5  domicile=camp
田所2  nomad_government                herd=696.96   provisions=0       domicile=yurt
陆氏   celestial_government            herd=0        provisions=0       domicile=east_asian_estate
```

### 4.2 根因

`biography.py:641-648`：

```python
if p.get("herd") is not None:
    hv = _num1(p["herd"])          # _num1(0) → "0"
    if hv:                          # 字符串 "0" 为真 → 写出「牧群0」
```

`provisions` 已做 `pv != "0"` 判定，`herd` 漏了；且未按毡帐类型门控。

### 4.3 方案

`facts._protagonist`（`facts.py:4519-4530`）已带出 `domicile_type`，据此把
`p["herd"]`/`p["provisions"]` 改为**只在对应domicile下产生**：

- `domicile_type == "yurt"`（或键 `x_c_nomad_*`）→ 写「牧群N」（N=0 时省略）；
- `domicile_type == "camp"`（或政体 `landless_adventurer_government`）→ 写「口粮N」（0 时省略）；
- 其余（庄园/领地）→ 两者皆不写。

即把 0 值判定移到 facts 层（单一出口），`biography.py` 只做 `if p.get("herd") is not None` 的渲染。

## 5. `兵部：任清（兵部尚书）` 信息重复

### 5.1 证据

提示词：`朝廷职司：政事堂：路岩、御史台：徐商、枢密院：卢彦方（枢密使）、吏部：孙浣（吏部尚书）、
户部：崔玙、礼部：郑从谠、兵部：任清（兵部尚书）、刑部：张武（刑部尚书）、工部：张重颖（工部尚书）`

### 5.2 根因

1. `facts.py:2030` 输出形态就是 `f"{base}：{nm}（{off}）"`（base=户部/兵部…，off=兵部尚书）。
2. `_MINISTER_OFFICE_KEYS`（`facts.py:1806-1815`）缺 户部/礼部 的本地化键
   （实测 `minister_revenue`/`minister_rites` 在本地化表里**不存在**），
   于是这两部落到 `title_base_name`（=户部）→ `off == base` → 不写官职词（所以它们反而没重复）。

本地化表实测可用键：`minister_personnel`=吏部尚书、`minister_war`=兵部尚书、
`minister_justice`=刑部尚书、`minister_works`=工部尚书、`minister_censor`=御史大夫、
`minister_grand_marshal`=枢密使、`minister_chancellor`=宰相、
`councillor_steward_celestial_government_imperial`=户部尚书、
`councillor_court_chaplain_celestial_government_imperial`=礼部尚书。

### 5.3 方案

1. 补齐 `_MINISTER_OFFICE_KEYS`：新增 `e_minister_of_revenue`、`e_minister_of_rites`、`e_minister_chancellor`；
   并把取值改成**候选链**（`minister_X` → `minister_X_male` → `councillor_*_celestial_government_imperial` → `title_base_name`），
   键名缺失时不再退化成「户部」。
2. `_current_ministers` 输出统一为 **`{官职词}{人名}`**：
   `兵部尚书任清`、`户部尚书崔玙`、`礼部尚书郑从谠`、`枢密使卢彦方`、`御史大夫徐商`、`宰相路岩`；
   官职词确实取不到时才退 `{base}：{nm}`。
3. `_minister_office` 是 `official_title` 的共用出口（`facts.py:1789-1791`），补齐键同时修正
   「朝廷职司持有者的官职名」。

## 6. 陆裕光文化=黎人（应为布僮人）

### 6.1 证据

```
熔件 melt_878: 48333 陆裕光 无 culture 字段（未成年人不存文化）, alive_data.languages=["language_tai"]
缓存 48333: culture=null, family.father=38682（culture=185 bouxcuengh）
Facts.culture(48333)          = 黎人      ← 错
Facts.culture_template(48333) = hlai
cl._culture_template_of(48333) = bouxcuengh  ← 父系链给出的正确答案
language_tai 的候选文化: 48 hlai(黎) / 184 tai / 185 bouxcuengh(布僮) / 192 tujia
```

### 6.2 根因

`facts.culture_template`（`facts.py:2855-2882`）顺序是：
自身文化 → **语言反查（`_lang_to_tpl`，无序取 `cands[0]`）** → 亲属链/宗族兜底。
语言反查取到字典序最先的 `hlai`，父系链（会给出 `bouxcuengh`）根本没机会执行。

### 6.3 方案

把 `facts.culture_template` 的顺序改为 **自身文化 → `cl._culture_template_of`（父系线→同胞→宗族→母→语言）**；
同时给 `cache_lib._culture_template_impl` 第 6 步（`cache_lib.py:855-863`）补上
「多文化共享同一语言时优先有父名规则的模板」的择优逻辑（与 `facts.py:2869-2878` 同口径），
避免换序后在无父系可推的角色上退化。

CK3 规则：子女文化随父系（父→母→宗族）优先于「共享语言」的反查，
本改动即按此排序。验证需回归 `experiments/verify_tadokoro2.py`（田所2）与 v27 上下文度量。

## 7. 元信息泄露（`出身自定` 等）

### 7.1 证据与全量排查

提示词里出现（每个提示词一次，共 16 次）：

```
先世无考（出身自定，史无可考，无父母谱系）。
```

本纪篇另有：

```
本篇传主为自定义出身，先世无考：资料未载其父母名姓与家世谱系，开篇以「起于何时何地、如何发迹」为纲书写其出身，
```

## 9. `妻室商州刺史陆荣廷`

### 9.1 证据

## 11. 叠溪寋的宗教/文化：数据在，渲染丢

### 11.1 调查结论（这就是「游戏里读得到、存档里读不到」的真相）

**存档里是读得到的。** 逐档实测 `43603 叠溪寋`：

```
melt_870/871  → living           culture=166(羌) faith=136(正一派)
melt_872…879  → dead_unprunable  culture=166(羌) faith=136(正一派)   ← 阵亡后一直在
缓存 player_38682.json / 43603: culture=166, faith=136
```

CK3 的实现原理：角色死亡时**不是**删除角色对象，而是把它移进
`characters.dead_unprunable`（被宗族/记忆/头衔引用、必须保留）或
`characters.dead_prunable`（可回收），**对象字段（culture/faith/dna/traits/dead_data）原样保留**；
游戏的角色窗/通知弹窗读的就是这个对象，所以永远读得到。
`dead_data` 里只多出死亡日期、死因、凶手、`liege/title` 等，**不含** culture/faith
（culture/faith 一直挂在对象顶层）——这正是「看 dead_data 看不到、看角色却看得到」的原因。
我们的 `load_melt` 把三段都并进 `all_characters`（`cache_lib.py:418-423`），所以数据本就在手里。

真正丢在渲染层：

- `_profile_needed_ids`（`facts.py:4643-4671`）的白名单只收
  亲属 ∪ 结友/结仇 ∪ 宫廷任官，**谋害对象不在内**（`successful_murder` 未列入 `REL`）；
- `_character_profiles(f)` 对 43603 返回 `{}`（实测）；
- 受害者档案（含 `culture/faith`，`facts.py:5467-5468`）只在《刺客列传》里渲染，
  而《刺客列传》的门槛是**击杀 >5**（`biography.py:441/1678`）；陆氏只杀 2 人 → 整篇不生成；
- 时间线谋杀行只写「（839年生）」（`facts.py:3980-3985`），不带族属/信仰。

### 11.2 方案

1. 把**主角的谋害对象**并入档案白名单：`_profile_needed_ids` 的 `REL` 判定补
   `successful_murder`（victim 侧）与缓存死亡记录 `killer==pid`（口径与 `_kill_entries` 一致）。
2. 时间线谋杀行补族属/信仰：`（839年生，羌人，信正一派）`（`facts.py:3980-3985`，取值走 `f.culture/f.faith`，
   缺失则整段省略，不写「不详」）。
3. README「已知限制」补一条：解释 dead_unprunable/dead_prunable 的保留机制（把本次调查结论固化下来）。

## 12. 满篇「无可考」：兜底为何这么多

### 12.1 量化（**按密度看，不是按绝对数**）

兜底式按语口径 = `无考|不可考|无可稽|不详|未详|史册不载|史不载|无明文|无一语|史无`：

```
陆氏 十年传 : 16 处 / 8,939 字符  = 1.79 处/千字
陆氏 终传   : 21 处 / 8,524 字符  = 2.46 处/千字
田所 十年传 : 12 处 / 24,972 字符 = 0.48 处/千字
田所 终传   :  7 处 / 28,193 字符 = 0.25 处/千字
田所2 十年传:  7 处 / 32,748 字符 = 0.21 处/千字
田所2 第2个十年: 16 处 / 21,627 字符 = 0.74 处/千字
```

陆氏只生成 3 篇（无《列传》《刺客列传》），全文仅 8.5–8.9k 字符，
**兜底按语密度是田所的 3–10 倍**——读者感受就是「满篇无可考」。
（单看「无考」二字：陆氏 4+4 处，田所 8/5/4/7 处；密度差主要在「不详/史无明文」这一类。）

提示词（陆氏段 42350–43600，共 14 次调用、35,849 字符）实测：
`出身自定` 14 次、`自定义出身` 2 次、`无考` 26 次、`不详` 2 次。

**提示词里并没有大量「不详」兜底串**（实测 `族属不详/信仰不详/官制不详/死因不详/特质不详` 在陆氏提示词中**全部为 0 次**）。
「无可考」是**模型自己写的**，触发链有四条：

1. **程序直给负向锚点**：`先世无考（出身自定，史无可考，无父母谱系）` —— 一句里塞了 2 个「无考」，
   **14 条提示词每一条都出现**。模型照抄。
2. **提示词直接教它写这句**：`biography.py:1262`「未载则省去、**以「先世无考」带过**」。
3. **回贴放大**：总纲（含「无考」）被原样植入 6 条开篇提示词（`biography.py:1268`），
   开篇摘要又进纪事（`biography.py:1315-1316`）——一次「无考」在 3 层里复制。
4. **规则口径**：`WORLD_FRAME_RULE`（`biography.py:61-64`）「资料未提供的**视为不存在或未知**」，
   与 `NONFICTION_RULE`「资料未提供的内容简写或略去」互相打架，模型选了「写考据按语」而不是「略去」。
   叠加陆氏本身真缺数据（无父母、无出生地、谋杀动机不在存档）→ 密集触发。

### 12.2 方案

1. 删掉负向锚点：`facts` 侧只保留「先世（父母名姓、谱系）资料未载」（见问题 7），
   不再出现「无考/史无可考」字样；`biography.py:1262` 的「以「先世无考」带过」删除。
2. `WORLD_FRAME_RULE` 改正向、并统一到「略过」：
   「本传所写世界完全由本提示词资料构成；所有人物、家族、官职、事件、日期、数字一律以资料为准，
   资料未载之处，行文径入下一事。」
3. 新增一条正向行文规则（进全部 system 提示词）：
   「「行文落笔」: 每一句都落在具体的人、时、地、事上；叙述自有资料可据的部分往下推进。」
4. 事实侧不产生新的负向串：`facts.py:5452` `（死因不详）` 改为**整段省略**；
   `facts.py:3014/3034/3143`（族属/信仰/官制不详）与 `facts.py:4414`（特质不详）在
   进提示词的行里**改为不输出该分句**（`biography.py:587-590` 已是「以不符结尾才跳过」的口径，统一到 facts 出口）。
5. 验收指标：重跑陆氏后兜底式按语 **≤ 0.5 处/千字**（对齐田所 0.21–0.48），
   且 `无考|不可考` 全篇 ≤ 2 次（仅保留「先世资料未载」这一处可选项）。
