# 修复方案 v34b · 柳特佩特「受封萨莱诺亲王国」（头衔创建措辞 + 头衔事件日期）

对象战役：`output/柳特佩特`（玩家 id 38653，潘杜尔夫·柳特佩特，848–878 第 1 个十年传记，
as_of 878.1.1，快照 `output/柳特佩特/data/snap_38653_878.1.1_d1.json`）。

触发：用户指出成稿写「874年4月26日，贝内文托亲王潘杜尔夫·柳特佩特受封萨莱诺亲王国」，
而该头衔是玩家在游戏里**手动创建**的（并非受人册封）。

调查方式：静态读码 + 缓存/熔件双源核对 + 游戏本体文件与本地化表查证。

---

## 零、结论速览

| 现象 | 根因（一句话） | 归属层 |
| --- | --- | --- |
| 正文写「受封萨莱诺亲王国」 | `style.TITLE_GAIN_VERBS["created"] = "受封"`（v28 为世族庄园定的词）；而 `reason=created` 的游戏自有文案是「**我创建了**X」，title history 亦记 `874.4.25 created(holder=玩家)` | style + facts（程序端） |
| 日期晚一天（记忆 874.4.26 / 史册 874.4.25） | 游戏的 ascended 记忆由 `title_event.9900`（`cooldown = { days = 1 }`）**次日**才落，`creation_date` 常晚 0~1 天 | facts（程序端） |

两句同源：**程序把「本人创设头衔」写成了「受人册封」，又把记忆日期当成了事件日期**；
模型只是逐字抄了这句事实（成稿第 44、196 行），不是幻觉。按项目铁律（prompt-last），
两处都改程序。

## 一、根因（证据链）

### 1.1 事实句的出处

`facts._mem_sentence`（`facts.py` 的 `TITLE_VAR_TYPES` 分支）按 memory `vars.reason`
查 `style.TITLE_GAIN_VERBS` 出词：

```python
if mem.get("type") == "ascended_throne_memory":
    verb = TITLE_GAIN_VERBS.get(reason)      # created → 「受封」(旧)
    return f"{owner}{verb}{title}。"
```

→ `874年4月26日，贝内文托亲王潘杜尔夫·柳特佩特受封萨莱诺亲王国。`

### 1.2 缓存与熔件双源：该头衔确由玩家本人创设

缓存的玩家记忆（`output/柳特佩特/data/player_38653.json`，memory id 30035）：

```
874.4.26  ascended_throne_memory
          participants {flavor_character: 12899 古艾费尔·道费尔}
          vars  reason=created, landed_title=2258
```

熔件 `melt_878_01_01.json` 的头衔 2258 `d_salerno`：

```
key=d_salerno  holder=38653(玩家)  capital=2259(c_salerno)
history = {…, 861.8.19: 12899, 872.11.26: {type: destroyed, holder: 12899},
                874.4.25: {type: created,   holder: 38653}}
date=874.4.25
```

即：萨莱诺伯爵领 872.11.26 被玩家征服（`c_salerno` 同日 `conquest→38653` + `granted→15445`），
公国头衔 `d_salerno` 随之废弃；17 个月后，持有该法理领地（首府 c_salerno）的玩家**自己**
把公国头衔创设出来。**没有册封人**，故「受封」与史料不合。

### 1.3 游戏本体口径（权威依据）

本地化表（`data/localization.json`，取自游戏 `localization/simp_chinese`）：

```
ascended_throne_memory_desc_intro_created = 我创建了[ROOT.Var('landed_title').Title.GetBaseName]
game_concept_created                      = 创建
```

记忆类型的描述 trigger（游戏 `common/character_memory_types/character_memories_1.txt`）：

```
triggered_desc = { trigger = { var:reason ?= flag:created
                               var:landed_title = { any_past_holder = { this != scope:owner } } }
                   desc = ascended_throne_memory_desc_created }        # 「在一段废弃期后」
triggered_desc = { trigger = { var:reason ?= flag:created }
                   desc = ascended_throne_memory_desc_created_first }  # 「作为一个新头衔」
```

→ 游戏的 created 分两档。萨莱诺公国此前另有主人（839–872 六任），属「废弃期后」→ **重建**；
无前主的新头衔（如陆氏 `x_nf_552`）属「作为一个新头衔」→ **创建**。

### 1.4 日期为什么晚一天

游戏 `events/title_events.txt` 的 `title_event.9900`（`cooldown = { days = 1 }`）
负责落 ascended/失落头衔记忆，由 `common/on_action/title_on_actions.txt` 在头衔变动后
触发 → 记忆日 = 事件日 + 0~1 天。本档实测：title 2258 史册 874.4.25 / 记忆 874.4.26；
全档 1081 条 `created` 记忆中 693 条同日、312 条 +1 天。
title history 的条目日期才是事件当天。

## 二、拍板口径（用户已确认）

1. **动词**：`created` → 「创建」（首建）/「重建」（此前另有主人，废弃后重立），
   沿用游戏 `desc_created_first` / `desc_created` 两档。
2. **范围**：领地头衔与 `x_nf_` 家族庄园（毡帐等 `x_` 同办）一视同仁。
3. **日期**：头衔得失句改用 title history 事件日；取不到历史条目时回退记忆日期。

## 三、改动清单

### 3.1 `style.py`

- `TITLE_GAIN_VERBS["created"]`：`"受封"` → `"创建"`，注释记明依据（游戏文案「我创建了X」）。
- 新增 `TITLE_GAIN_CREATED_VERBS = {"first": "创建", "restored": "重建"}`（对应游戏两档 trigger）。

### 3.2 `facts.py`（措辞）

- `Facts.title_had_other_holder(tid, cid, date)`：头衔在 date（含）前是否另有主人 —
  与游戏 trigger `any_past_holder = { this != scope:owner }` 同义；`history` 兼容
  裸 id / `{type, holder}` / 同日事件列表，`holder=None` 不计。
- `_mem_sentence`：`reason == "created"` 时按上式分档取词（其余 reason 行为不变）。

### 3.3 `facts.py`（事件日期）

- `Facts.mem_date(cid, mem)`：头衔得失记忆（`TITLE_VAR_TYPES`）取 title history 事件日，
  其余记忆仍取 `creation_date`。
- `Facts._title_event_date(tid, cid, mem_date, reason, lost)`：取 `date <= mem_date` 的
  最近一条 — 先认 `type == reason` 的条目（`destroyed` 失去条目的 holder 是原主也能命中），
  无同类再按持有侧兜底（得：holder==cid；失：holder!=cid）；与记忆日相差超过
  `_TITLE_DATE_NEAR_DAYS = 31` 天（近似天序，防误配久远旧事）则回退记忆日期。
- 四个出句点改用 `mem_date`（事件日期与去重键同源）：
  ① `_timeline`（`seen_keys` / `idents` / 事件日期元组）；
  ② `_character_profiles`（as_of 截断 + 【人物档案】【传主行迹】）；
  ③ 刺客列传条目的事件行；④ `_house_war_nodes` 的「失守头衔」节点。

### 3.4 顺带修掉的两个连带问题

- **恩怨节点同日并存**（`house_feuds`）：旧实现按日期把「同日的战争类旧句」整体换成新节点，
  改用 title history 事件日后，「战胜X」（875.7.2）与「X失守那波利伯爵领」（原 875.7.3）
  撞到同一天，「战胜」节点被自己删掉。现改为**只在关系流水里做同日取代**，
  本函数补的因果节点之间同日并存（同日战胜并夺地是常态）。
- **`experiments/verify_lushi.py` 陈旧断言**：第 7 组仍断言档案须出现「先世资料未载」，
  而该按语自 v30（`修复方案_菲利普4.md` 问题4）已整行撤除 → 该断言自 v30 起恒 FAIL。
  本轮改为「须不出现」。

### 3.5 测试与文档

## 五、边界与失败模式

- **熔件剪除/无该头衔**：`title_had_other_holder` 返回 False → 「创建」；日期回退记忆日期
  （柳特佩特档 `created` 记忆中 26 例 title 无 history）。
- **同日多事件列表**（如 `c_salerno 872.11.26` 的 `[{conquest,38653},{granted,15445}]`）：
  逐条展开判，得主取本人那条，失主先认 `type == reason`。
- **`holder=None` 的 destroyed 条目**（如 `d_mazovia`）：不计「另有主人」；
  `type=destroyed` 的失去记忆靠 type 命中日期，不靠持有侧。
- **记忆日早于史册日 / 相差超过 31 天**：回退记忆日期，行为与旧版一致。
- **十年窗口**：第 1 个十年的下界为 as_of−10 年年初（`_decade_lower_bound`）；
  头衔事件前移一天后若跨到下界之前，该条按窗口规则自然移出本期（正确行为）。
- **其它 reason 不受影响**：`granted` 仍「受封」、`revoked` 仍「夺得」、行政制
  `appointment*` 仍「受任」；缓存 schema、提示词、板块结构均无改动。
