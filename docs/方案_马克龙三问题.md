## 0. 摘要（三问题 → 根因 → 修法）

| # | 现象 | 根因（代码定位） | 修法（全程序端） |
| --- | --- | --- | --- |
| 1 | 模型不知道监禁者是谁；越狱整条消失；不知道出狱方式（获释/逃脱）；妾室被写成「先婚后囚」 | ① `style.MEMORY_TEMPLATES["imprisoned"]`＝「{name}被囚。」（style.py:455）不用参与者槽；② `escaped_from_prison_memory` 在 `PARTICIPANT_SLOTS`/`MEMORY_TEMPLATES`/`MODULE_TABLE` 三处均未登记；③ `MODULE_SLICE[("jiashi","mid")]`（facts.py:4951）不含囚禁模块；④ 强纳妾的日期在 `opinions.active_opinions` 的 `forced_me_concubine_marriage_opinion.start_date`，项目只读了 `scripted_relations`（facts.py:3663） | 模板改用 `{other}` 出监禁者；越狱补齐四处登记并按「获释/越狱」分词；家室列传切片补囚禁模块；缓存逐档差分纳妾类 `temporary_opinion`，出「强纳为妾」句 |
| 2 | 「不法之徒」等其实是一组子轨道（强盗/骗子/窃贼/偷猎者/掠夺者），按经验值分档换效果 | `localization.build_trait_names`（localization.py:1143-1153）取 name 块**第一个** desc，而游戏把**最高档**名写在最前；`trait_xp_amounts` 从未被读取 | 建轨道表＋档位名表（schema 3）；缓存记 `trait_xp` 逐档差分；`_trait_name` 按 XP 求当前档名，并输出子轨道与档位 |
| 3 | 「此婴儿未知其名，未知其母，只知为埃马努埃尔之血脉」（妻只有一位） | `child_stillborn` / `child_premature` 的 participants 槽 `mother` 未登记进 `PARTICIPANT_SLOTS`（facts.py:138），模板也不含 `{other}`（style.py:461-462） | 两型补槽位；模板写「{name}之妻{other}产下死婴。」等，自指时回退无对象版 |

三问题**均不动提示词**（对齐 `.agents/skills/no-negative-prompts` 的 prompt-last 铁律）。

## 1. 监禁者与出狱方式（问题1）

### 1.1 数据其实全在（先给结论）

游戏 `common/character_memory_types/character_memories_1.txt` 四型监禁记忆都带对手方槽：

| 记忆型 | participants | 游戏原文（本地化表实测） |
| --- | --- | --- |
| `imprisoned` | `imprisoner` | 我被[imprisoner]囚禁 |
| `imprisoned_other` | `imprisoned` | 我囚禁了[imprisoned] |
| `released_from_prison_memory` | `imprisoner` | 我被[imprisoner]释放 |
| `escaped_from_prison_memory` | `imprisoner` | 我从[imprisoner]的监禁中逃脱 |

**出狱方式只有互斥两种**（引擎口径，非脚本可分辨的更多语义）：
`common/on_action/prison_on_actions.txt:288` 在未置 `escaped_from_prison_flag` 时建
`released_from_prison_memory`；`common/scripted_effects/00_prison_effects.txt:2088` 建
`escaped_from_prison_memory`。赎金/赦免/仁慈都走同一条 `released` —— 存档不记释放缘由，
**能读出的「方式」就是「被释放」与「逃脱」的对立**。

### 1.2 实证（马克龙档 38677）

| 角色 | 记忆（缓存 `player_38677.json`） |
| --- | --- |
| 主角 38677 | `imprisoned`(869.10.16, imprisoner=12278 安乔·瓦斯科涅) ＋ `escaped_from_prison_memory`(同日, 同监禁者) |
| 妻 15682 | `imprisoned`(868.11.8, 12278) ＋ `released_from_prison_memory`(869.3.12, 12278) |

快照 `snap_38677_878.1.1_d1.json` 实际下发给模型的面（`tools/diag_snap_block.py jiashi_lead`）：

- **家室档案行**（走 `_mem_sentence`）：「868年11月8日，西法兰克王国公主埃芒特鲁德·加洛林**被囚**。」
  「869年3月12日，…**获释**。」→ 监禁者丢失，两句不配对；
- 同一块的**相关年表**（走 `_pair_imprisonments`）：「868年11月8日，阿马尼亚克伯爵可怖者安乔·瓦斯科涅囚禁…公主…，4个月后获释。」→ 只在年表里对；
- 主角 869.10.16 的越狱：`benji_mid` 只有「安乔·瓦斯科涅囚禁埃马努埃尔·马克龙。」，**越狱整条不存在**；
- 《家室列传》纪事块（`jiashi_mid`）**完全没有囚禁料** → 模型写「囚禁之人，后世皆指为伯爵本人」
  （即 v31 遗留 1，见 `docs/修复方案_马克龙八问题.md` §12.6）。

### 1.3 妾案（菲利普档 38691）：存档里有「强纳为妾」的确切日期

- 妾 17039 戈迪娜·迭戈斯：`imprisoned` 878.2.6（监禁者＝主角 38691）、
  `released_from_prison_memory` **880.1.1**。
- 妾 15511 埃尔斯威思：囚 876.11.5、释 **876.11.13**。
- `opinions.active_opinions` 实测（`tools/diag_philip_opinions.py`）：
  `{owner:17039, target:38691, temporary_opinion:{modifier:"forced_me_concubine_marriage_opinion", start_date:"880.1.1"}}`、
  `{owner:15511, target:38691, …, start_date:"876.11.13"}` —— **强纳妾日期 ＝ 释放日期**。
- 机制吻合：`concubine_on_accept_effect`（`00_marriage_interaction_effects.txt`）在
  `is_imprisoned` 时 `release_from_prison = yes` 并加「将我强行纳为[侧室]」好感；
  `make_concubine_interaction` 的候选表含 `every_prisoner` —— 纳妾即释放。
- 本地化：`forced_me_concubine_marriage_opinion = 将我强行纳为[concubine|E]`，
  全档 22 条、`concubine_with_monogamous_faith_opinion` 5 条（一样带 `start_date`）。

**模型为何写成「先婚后囚」**：二轮稿（`崔佛·菲利普(849)_传记_第2个十年_888_01_01.md:114`）
「戈迪娜·迭戈斯**嫁入崔佛帐下的年份未见于簿册**，唯知878年…囚禁」——事实面只有
「妾：戈迪娜」（无日期的状态）与「878年囚禁…1年10个月后获释」，纳妾日期从未下发。

### 1.4 根因（代码定位）

| # | 位置 | 缺陷 |
| --- | --- | --- |
| R1 | `style.py:455` | `"imprisoned": "{name}被囚。"` — 模板不含 `{other}`，监禁者丢失（`PARTICIPANT_SLOTS` 里本已有 `imprisoner`） |
| R2 | `facts.py:138` / `style.py` / `facts.py:4900` | `escaped_from_prison_memory` 三处未登记 → `_mem_sentence` 返回 None，越狱无句、无模块、无槽位 |
| R3 | `facts.py:4951` | `MODULE_SLICE[("jiashi","mid")]` 无「囚禁入狱/获释出狱」→ 家室列传纪事无囚禁料 |
| R4 | `facts.py:5407` `_pair_imprisonments` | 只把 `released_from_prison_memory` 当出狱；越狱不配对，同日的「囚＋逃」不合成一句 |
| R5 | `facts.py:5277` `_IDENT_TYPES` | 未含 `escaped_from_prison_memory`（配对/合并需要带身份槽） |
| R6 | `facts.py:3517` `imprison_duration` | 只认 `released`，逃脱者被算作「卒时仍在狱中」 |
| R7 | `facts.py:3663` `_player_opinion_index` | 只读 `scripted_relations`，`temporary_opinion` 整节未用 → 强纳妾日期不可见 |
| R8 | `biography.py:37` `POLITICAL_TYPES` / `facts.py:189` | 亦无 `escaped_from_prison_memory`（朝局篇取材） |

### 1.5 方案（全部程序端）

1. **style**：`imprisoned` → `"{name}为{other}所囚。"`（无 other 回退旧句「被囚」）；
   新增 `escaped_from_prison_memory` → `"{name}自{other}的监禁中逃脱。"`（无 other 版「越狱脱身」）。
2. **facts**：`PARTICIPANT_SLOTS` 增 `"escaped_from_prison_memory": "imprisoner"`；
   `_IDENT_TYPES` 增同型；`MODULE_TABLE` 的「获释出狱」并入 `escaped_from_prison_memory`
   （**待拍板**：或单列「越狱脱逃」模块）；`biography.POLITICAL_TYPES` 同步。
3. **facts `_pair_imprisonments`**：`outs` 同时收 `released` 与 `escaped`，正文按方式分词：
   - 释放 → 「…囚禁X，4个月后获释。」（沿用 `prison_released`）
   - 逃脱 → 「…囚禁X，4个月后越狱逃脱。」（新增 `prison_escaped`）
   - 同日囚＋逃（主角 869.10.16）→ 「…囚禁X，**当日越狱**。」
4. **facts 切片**：`MODULE_SLICE` 的 `("jiashi","lead")` 与 `("jiashi","mid")` 补
   「囚禁入狱」「获释出狱」（纪事不再缺囚禁料，直接消掉 v31 遗留 1）。
5. **facts `imprison_duration`**：`outs` 收 `escaped`（逃脱者不再算仍在囚）。
6. **cache**：新增 `_diff_opinions`（与 `_diff_hooks` 同构）——遍历
   `melt.opinions.active_opinions`，只收 `owner==玩家 or target==玩家` 且 `temporary_opinion.modifier`
   属纳妾/婚姻白名单者，记 `{owner, target, modifier, start, expiration, first, lost_at}`；
   `EMPTY_CACHE` 增 `"opinions": {}`。
7. **facts**：新增 `Facts.forced_concubine_lines()` ——「880年1月1日，主角强纳戈迪娜·迭戈斯为妾
   （同日自狱中释出）。」；下发《家室列传》（lead 或 mid，**待拍板**）。
8. **facts 家室行**：妾/妻若与主角有监禁对，把该对联到其人一行内（现在家室档案行与年表分列，
   信息不同步）。

### 1.6 验收

- 快照里主角 869.10.16 出现「…囚禁X，当日越狱」；
- 妻的家室档案行写作「阿马尼亚克伯爵可怖者安乔·瓦斯科涅囚禁…公主…，4个月后获释。」，
  不再有孤立「被囚。」「获释。」；
- `jiashi_mid` 含囚禁对；
- 菲利普档重跑：家室列传出现「880年1月1日强纳戈迪娜·迭戈斯为妾」，
  且与「878年2月6日被囚、1年10个月后获释」并列 → 模型不再写「嫁入年份未见于簿册」。

## 2. 特质子轨道（问题2）

### 2.1 机制（游戏定义实证）

`common/traits/_traits.info` 明载：

```
### Level tracks
Traits can be marked as levelling and gain different bonuses based on how much XP
a character has within that track. A trait can have one or multiple tracks …
Each track can contain entries with a required XP score from 0-100 inclusive …
If only one track is needed then a short hand is provided which creates one track named after the trait itself.
```

- 多轨 `tracks = { … }`；单轨简写 `track = { … }`（轨名＝特质键）。
- 实测（游戏＋启用 Mod）：**85 个特质带 XP 轨道，共 119 条轨道**。
  代表样本：

| 特质 | 轨道（本地化名） | 档位阈值 |
| --- | --- | --- |
| `gallowsbait` 不法之徒 | 强盗 / 骗子 / 窃贼 / 偷猎者 / 掠夺者 | 20/40/60/80/100 |
| `lifestyle_hunter` 猎手 | 猎手 / 驯鹰师 | 50/100 |
| `tourney_participant` 竞技选手 | 步战 / 弓箭 / 骑术 / 智慧 | 30/65/100 |
| `lifestyle_traveler` 旅行者 | 漫游者 / 老成者 | 命名档位 50/100 |
| `infirm` 体弱多病、`scarred` 伤疤、`confucian_education` 儒家教育 … | 单轨（轨名＝特质名） | 25/50/75/100 等 |
| 将略类：后勤师/围城者/进攻专家/机变者/劫掠者… 共 19 个 | 单轨 | 33/66/100 |

### 2.2 存档怎么存（已破解并 100% 验证）

角色字段 `trait_xp_amounts` 是与 `traits` **顺序对齐的扁平数组，每条轨道一个数**；
多轨特质按定义里轨道的声明顺序占位。

拟合（`tools/diag_macron_xpfit.py`，马克龙 879 档全量 3987 个持轨道特质角色）：
**命中 3987 / 不符 0**。样例：

```
13227 Hunfrid  traits=[deceitful, paranoid, forgiving, education_intrigue_4, schemer, gallowsbait]
               xp=[20, 0, 20, 0, 0]     → 强盗20、骗子0、窃贼20、偷猎者0、掠夺者0
13346 阿居尔   traits=[…, gallowsbait, adventurer]  xp=[0,0,0,0,0,10]  → 掠夺者10
46312 Nalka    traits=[…, lifestyle_hunter, lifestyle_traveler] xp=[75,0,0,0]
               → 猎手75、驯鹰师0、漫游者0、老成者0
```

命名档位键（`trait_second_level` / `trait_third_level`，`scarred`、`lifestyle_traveler` 在用）
对应 50 / 100（实证 `scarred` 的 `name` 块：`value < 50` → 一级、`= 100` → 三级）。

**显示名与效果都取得到**：

- 轨道名：`trait_track_<track>`，**119/119 全命中**（强盗/窃贼/骗子/偷猎者/掠夺者/猎手/驯鹰师/
  后勤师/围城者/进攻专家/河流专家/行奇迹者…）；描述 `trait_track_<track>_desc` 亦全命中。
- 档位效果：`MOD_<大写下划线>` 键 **659 个**（`general_opinion`→大众好感、
  `martial`→[martial|E]、`attraction_opinion`→[attraction|E]好感度…）；
  少数键缺（`glory_hound_opinion`/`parochial_opinion`/`max_murder_schemes_add`），整项略去即可。

### 2.3 现状 bug（用户所述现象的正式根因）

`localization.build_trait_names`（localization.py:1143-1153）取 `name` 块里**第一个** `desc`，
而游戏惯例是**把最高档名写在最前**，故 **54 个「按 XP 换名」的特质全部显示最高档名**
（`tools/diag_trait_levelnames.py`）：

| 特质 | 现用名（＝最高档） | 基础名 | 玩家/该档实况 |
| --- | --- | --- | --- |
| `lifestyle_reveler` | 传奇的狂欢者（trait_reveler_3） | 狂欢者 | 马克龙主角 38677 的 XP=**0** → 游戏内显示「狂欢者」 |
| `aggressive_attacker` | 闻名的陷阵者 | 激进的进攻者 | 仅少数人进档 |
| `logistician` | 后勤大师 | 后勤专家 | — |
| `reaver` | 恐惧化身 | 劫掠者 | — |
| `confucian_education` | 至圣贤人（五档） | 儒家教育 | — |
| `lifestyle_traveler` | 旅行者（反向：档位名顺序与触发顺序不一致） | — | 高 XP 者被写成低级名 |

快照实证：`protagonist.traits` 里写作「阅历**传奇的狂欢者**」（`snap_38677_878.1.1_d1.json`）。

### 2.4 方案（全部程序端）

1. **数据层** `localization.build_trait_names` → `schema: 3`（`python localization.py traits` 一键重建）：
   - `traits`：改为**基础名**（`name` 块里不带 `has_trait_xp` 条件的那条，或 `trait_<key>`）——
     旧缓存/查不到 XP 时也不会再显示最高档名；
   - `tracks`：`{trait: [{track, levels:[xp 阈值…]}]}`（含单轨简写）；
   - `level_names`：`{trait: [{cond, loc_key}]}`——按 `triggered_desc { trigger = {…} desc = X }`
     逐条配对（条件保留 `has_trait_xp` 的 track/比较符/值 与 OR/AND/NOT 结构）。
2. **cache** `extract_snapshot`：记 `rec["trait_xp"]`（扁平数组，附当档 traits 快照），
   逐档差分成 `trait_xp_history`（形态仿 `trait_history`：`{trait|track: [{from, xp, to}]}`，
   仅在数值变化时追加），旧缓存缺字段时回退「基础名」。
3. **facts**：
   - `_trait_name(table, key, xp=None)` 增档位名求值（小表达式求值器，约 60 行；条件不可解析时回退基础名）；
   - `trait_pairs` / `trait_groups` / `traits_sentence` 用当前档名；
   - 新增 `Facts.trait_track_lines(cid)`（与人句并列的确定性事实）：
     `不法之徒（强盗一阶、窃贼一阶；余途未入）`；
   - `trait_history_lines` 增「轨道进档」履历：
     `不法之徒·强盗（自872年起进至二阶）`（阈值跨界时记，逐档差分即已足够）。
4. **提示词端不新增要求**（轨道、档位、效果都是确定性数据；「为人」句自然写出即可）。

### 2.5 验收

- 快照 `protagonist.traits` 不再出现「传奇的狂欢者」，改为「狂欢者」；
- 持有 `gallowsbait` 的角色档案出现「强盗/窃贼/…」子轨道与其档位；
- 非 XP 特质（`brave` 等）显示名与现状逐字节一致（回归基线）。

### 2.6 待拍板

1. 子轨道呈现到哪一层：**(A)** 只修档位名 ＋ 括注子轨道与档位（推荐）；**(B)** 再加当前档位的
   效果修饰符（`MOD_*` 表可查，体积与可读性需权衡）；**(C)** 只修档位名，不列子轨道。
2. 档位词：一级/二级…（推荐，与游戏分档直接对应）或另择词（初窥/渐精/精通…）。
3. 轨道进档是否写入「特质履历」（推荐写）。

## 3. 夭折婴儿的生母（问题3）

### 3.1 证据

主角 38677 的记忆（`player_38677.json`）：

```json
{"id": 37168, "type": "child_stillborn",
 "participants": {"mother": 15682}, "creation_date": "876.8.27"}
```

游戏定义（`character_memories_1.txt`）：

| 记忆型 | participants | 游戏原文 |
| --- | --- | --- |
| `child_stillborn` | `mother` | 我的[母]生下一个死婴 |
| `child_premature` | `mother` | 我的[母]的孕期提前结束了 |

缓存内覆盖率（`tools/diag_macron_child.py`）：`child_stillborn` 11 条、
`child_premature` 26 条，**mother 槽 37/37 全在**（其中 5/12 条是母亲本人视角）。

传记原文第 161 行：「此婴儿未知其名，未知其母，只知为埃马努埃尔之血脉」；
事实面（`benji_lead`/`jiashi_mid`）确实只有「876年8月27日，…埃马努埃尔**婴儿夭折**。」。

### 3.2 根因

1. `PARTICIPANT_SLOTS`（facts.py:138-151）没有 `child_stillborn` / `child_premature`，
   `slot` 为 None 时虽会兜底取「第一个 int 参与者」，但**模板不接受 `{other}`**，取了也没用；
2. `style.MEMORY_TEMPLATES`（style.py:461-462）＝「{name}幼子夭折。」「{name}婴儿夭折。」——
   句子里根本没有母亲位；`name` 是记忆持有者（通常是父亲），于是模型只知道「埃马努埃尔的孩子」。

### 3.3 方案（程序端）

1. `PARTICIPANT_SLOTS` 增 `"child_stillborn": "mother"`、`"child_premature": "mother"`。
2. 模板按**配偶称谓性别化**：
   - `child_stillborn` → 「{name}之妻{other}产下死婴。」/ 女主角时「{name}之夫{other}…」
   - `child_premature` → 「{name}之妻{other}孕期提前结束。」
   （沿用 `Facts._is_female` 与既有「夫婿/妻室」性别化口径，v28 已立。）
3. **自指回退**：owner == mother 时不出「A之妻A」，改用无对象版
   「{name}产下死婴。」「{name}孕期提前结束。」（沿用 `_PEER_SLOT_TYPES` 的自指判定思路）。
4. 不下发「未知其母」这类按语（缺料按语不进提示词铁律）；母亲名由数据给出。

### 3.4 验收

- `benji_lead` / `jiashi_mid` / 家室档案行均出现「埃芒特鲁德…产下死婴」式句子，
  不再出现只有父名的「婴儿夭折」；
- 母亲自身视角的 12 条不出现「X之妻X」。

### 3.5 待拍板

1. 措辞：**「产下死婴」/「孕期提前结束」**（贴游戏原文，推荐）还是「小产」「殇于腹中」等？
2. 称谓式样：**「{name}之妻{other}」**（推荐）还是无性别「{name}与{other}的孩子产下即殇」？
   （后者在生母为侧室/情人时不会误称「妻」——**若取后者可一并绕开称谓性别化**。）
