## 问题 1：睦、立希被当成儿子 —— 提示词里根本没有性别，出生模板只会写「添子」

### 1.1 现象

第 1 个十年传（`田所浩二(843)_传记_第1个十年_890_01_01.md`）同一篇里自相矛盾：

```
第 37 行：其妻周子为诞一子，名之曰睦；二十七日，又诞一子，名之曰立希。旬月之间，连添二丁
第 147 行：其后祥子生于875年，秀吉生于877年……共添丁七人
第 159 行：880年6月12日，周子产下一女，取名睦。……6月27日，毗伽伊尔盖亦产一女，取名立希
第 235 行：同年，浩二添子，取名田所睦、田所立希
```

第 2 个十年传同样：`四子秀吉……五子睦生于880年6月12日`、`次室所出子睦、立希等`，而同一篇又写 `最幼之女田所爱音`、`长女结衣`。

缓存实测：睦 = 16807427（`female: True`）、立希 = 52501（`female: True`）、结衣 = 42955（`female: True`）、爱音 = 62967（`female: True`）——**游戏数据里性别齐全**。

### 1.2 根因：事实文本零性别信号，唯一的性别词是「子」

提示词里与睦/立希相关的全部原文（`logs/prompts.log` 38730–38749）：

```
田所立希，大和人，生于880年6月27日。          ← 档案无性别
父田所浩二，母毗伽伊尔盖，兄弟姊妹田所结衣、…   ← 亲属列表无性别
田所睦，大和人，生于880年6月12日。
父田所浩二，母周子，兄弟姊妹田所结衣、…
妻室周子、毗伽伊尔盖，子女田所结衣、田所秀茂、田所祥子、田所秀吉、田所睦、田所立希、田所素世。  ← 「子女」混排无性别
880年6月12日，色鬼田所浩二添子田所睦。          ← 记忆模板写死「添子」
880年6月27日，色鬼田所浩二添子田所立希。
```

模型能看到的**唯一**性别词就是「添子」，于是默认写成儿子；偶尔写对（爱音、结衣）是靠名字猜的，因此前后矛盾。

代码位置：

| 位置 | 现状 |
| --- | --- |
| `facts.py:158` | `"child_born": "{name}添子{other}。"`（写死男性） |
| `facts.py:159` | `"first_born": "{name}得长子{other}。"` |
| `facts.py:162` | `"twins_born": "{name}得孪生子。"` |
| `facts.py:3054` `_mem_sentence` | `tpl.format(name, other, title)`，模板无性别槽位，也不查孩子性别 |
| `facts.py:3351/3364` `_year_summary` | 出生类事件统一用动词「添子」合并（`births` → `verb="添子"`） |
| `facts.py:4127` `_character_profiles` | `prof["children"] = "、".join(...)`，无性别 |
| `biography.py:481-482` `_profile_lines` | `fam_bits.append(f"子女{p['children']}")`，无性别 |
| `facts.py:1907-1921` `prince_title` | 仅父/母头衔 ≥ 王国级才给「王子/公主」；主角是伯爵，子女无称号 |
| `biography.py:1291/1302` | 模块切分正则同样只认「得长子/添子」 |

### 1.3 顺带发现：缓存 `female` 字段从来没被写过

`cache_lib.char_record`（`cache_lib.py:613-634`）的字段模板**没有 `female`**；`extract_snapshot`（`cache_lib.py:1343-1365`）首见分支也从不复制 `c["female"]`。于是缓存里所有角色 `female` 都缺省，`bool(None) == False`。

好在 `facts.py` 的性别判断走的是**熔件全量索引 `self._chars`**（`facts.py:637`，`cl.all_characters` 含 living + dead_unprunable + dead_prunable），所以 facts 层的性别其实是对的；真正被这个缺陷伤到的是 `cache_lib` 自己的三处逻辑：

| 位置 | 后果 |
| --- | --- |
| `cache_lib.py:914-917` `_patronym_of` | 女性父名后缀（-dóttir 系）永远用男性后缀 |
| `cache_lib.py:1042-1049` `_parents_of` | 反查来的父母一律判为「父」；母亲只在 `family_data.mother` 显式存在时才正确（注释自承「子女 family_data 常为空」，即常见路径） |
| `cache_lib.py:1113-1119` `real_father_of` | 秘密生父候选只排除 `cc.get("female")`，而该值恒假 → 女性也可能被当成生父 |

### 1.4 修复方案（建议）

1. **`cache_lib` 持久化性别**：`char_record` 增 `"female": False`；`extract_snapshot` 首见时 `rec["female"] = bool(c.get("female"))`（有值时也覆盖，兼容旧缓存自愈）。
2. **`facts` 增统一入口** `Facts._is_female(cid)`：缓存有值用缓存，否则回退 `self._chars`（熔件），供全部调用点复用；把 `cache_lib` 三处逻辑改为优先缓存、熔件兜底。
3. **出生记忆按性别渲染**：`_mem_sentence` 对 `child_born` / `first_born` / `twins_born` 特判，取 `parts["child"]` 的性别：
   - 男：添子 / 得长子 / 得孪生子；女：添女 / 得长女 / 得孪生女；一男一女：得龙凤胎。
   - 模板保留原键，另加 `child_born_female` 等，避免影响其它调用点。
4. **`_year_summary` 同步**：出生按性别分组合并（`添子甲、乙；添女丙、丁`），不再一律「添子」。
5. **档案写明性别**：
   - 子女列表拆为 `子A、B，女C、D`（`facts._character_profiles` 增 `children_sons` / `children_daughters`，`biography._profile_lines` 按有值渲染）。
   - 每个子女的档案首行加性别：`田所睦，女，大和人，生于880年6月12日。`
6. **模型侧正向引导**（可选）：家室列传 req 补一句「子女一律按资料标注的性别书写」——只加正向要求，不出现否定词。

**影响面**：所有含子女/兄弟姊妹的传记；性别数据源不变，仅呈现方式变化。**验证**：新增脚本比对「改前/改后事实块」，确认除出生句与家庭句外零改动；断言睦/立希/结衣/素世/爱音全部为「女」。

## 问题 2：仇人判定 —— 只认「结仇记忆」的池子 + 在世优先 + 事迹门槛失效

### 2.1 现行判定规则（`biography.py:305-323`）

```
候选池 = 与主角有 became_rivals / became_grudge / became_nemesis 记忆的角色（双通道，biography.py:190-228）
      ∩ 结仇日期 ≤ as_of
过滤  = 记忆条数 > ENEMY_MIN_MEMORIES(=5)；池空则回退全体
排序  = ① 在世优先（_is_dead，biography.py:185-187）② 结怨最早
```

### 2.2 实测：田所的全部仇人只有 5 人

```
菅原类子      14784  870.12.28  12 条记忆  已死(893.11.11)  女
崔慎由        10436  875.12.26  13 条记忆  已死(881.2.18)   秦皇帝（875.6.23 夺位）
索皮·巴格拉图尼 16558  882.4.14   18 条记忆  已死(882.9.26)
埃塞尔斯威思   13874  887.7.2     8 条记忆  已死(888.6.29)
尤拉特        16796755 893.1.20   10 条记忆  在世
```

实跑 `_select_primary_enemy`：

```
as_of=890.1.1 → 菅原类子
as_of=900.1.1 → 尤拉特
```

### 2.3 为什么是菅原类子（三层原因）

1. **中国皇帝根本不在池子里。** 池子的定义是「有结仇记忆」。主角谋杀的五位唐皇帝（李漼/李儇/李文举/李伯玉/李润）是 `successful_murder` 受害者，没有任何 `became_rivals/grudge/nemesis` 记忆，永远进不了候选。唯一兼有「皇帝」与「结仇」身份的是 **崔慎由**（h_china 头衔 id 14036，875.6.23–881.2.18 在位，875.12.26 与主角结仇）。
2. **「在世优先」把唯一在世者推上首位。** 890 年那篇生成时（22:03，当时缓存只并到 890 档），菅原类子尚未死亡（她 893.11.11 才死），而崔慎由(881)、索皮(882)、埃塞尔斯威思(888)都已死 → 在世池只剩她一人，直接胜出。
3. **记忆数门槛挡不住「没事迹」。** 她有 12 条记忆，全部是 `married / relative_died / became_rivals / spouse_died / ce1_contracted_epidemic` 之类被动事件，**没有一条可写的行迹**。而 `ENEMY_MIN_MEMORIES` 只看条数。

### 2.4 放大问题的两个次生缺陷

| 缺陷 | 位置 | 后果 |
| --- | --- | --- |
| `传主行迹` 恒为空 | `facts.py:4142-4153`：`for mem in prof.get("memories") or []`，但 `prof` 字典（4081-4093）**从未写入 `"memories"` 键** → `prof["events"]` 永远是 `[]` | 罗元、菅原类子、尤拉特三篇的「传主行迹」实测全部是「（无行迹记录）」（prompts.log 38610/39336/41153）——即使选到崔慎由也一样没行迹 |
| `_is_dead` 不看 as_of | `biography.py:185-187` 只看缓存有无 `death` 记录 | 十年传里「卒于 as_of 之后」的角色被当成已死，在世优先失效 |

### 2.5 修复方案（建议）

1. **先修数据管道**：`_character_profiles` 用 `rec.get("memories")`（或 `prof["memories"] = rec.get("memories")`）填 `events`，让「传主行迹」恢复。这一条修完，菅原类子也会显示出婚配、丧父、与主角结仇等 12 条。
2. **`_is_dead` 支持 as_of**：`death.date > as_of` 视为在世。
3. **把「记忆条数」换成「事迹权重」**：给记忆类型打分（登位/战争/谋杀/囚禁/婚配/生育/结友 = 正分；亲属去世/患病/私通 = 低分或 0），候选按分数排序，`≥ N 分` 才入池；在世作为**并列时的次级权重**而非第一优先级。
   - 田所数据实跑预期：890 年候选分数 崔慎由（6 次登位 + 生子 + 结友）＞ 索皮（登位 + 生育 + 出质）＞ 菅原类子（全是被动丧亲）。
4. **是否扩大仇人语义（需你定夺）**：
   - 方案 A（保守）：仍只在「结仇记忆」池里排序，只修权重/行迹。890 年大概率选崔慎由（秦皇帝），符合你的期待。
   - 方案 B（扩大）：把「主角亲手杀害/囚禁的高位者」也纳入「宿敌」候选（唐皇帝们即入围），按受害者的头衔层级 + 与主角的因果链排序。这会让《列传·仇人》有时写成「刀下之鬼」的另一种列传，需要你确认是否符合体例。

## 问题 3：游牧动态头衔 —— 代码只读静态名，官职词没有游牧分支

### 3.1 游戏口径（实测游戏文件）

- `common/governments/00_government_types.txt`：`nomad_government` 有 `uses_culture_and_house_head_named_realms = yes`。
- 本地化键：`TITLE_NOMAD_NAME_HOUSE_HEAD = $CULTURE_COLLECTIVE$$DYNASTY_NAME$部` → 「可萨田所部」。
- 存档实测（`melt_900`，标题 4027 `c_khortytsia`，holder=38682）：

```
title_name_data.name                 = 也勒克河        ← 代码现在用的
title_name_data.specific_title_name  = 可萨田所部      ← 游戏显示用的
title_name_data.specific_map_name    = 可萨田所部      ← 地图显示用的
```

  逐档扫描（`experiments/diag_tadokoro2.py`）：892 年起 `specific_title_name` 一直为「可萨田所部」，`name` 始终是「也勒克河」。

- 官职词：`common/flavorization/00_title_holders.txt`

```
count_nomad_male_turkish = { tier=county governments={nomad_government} heritages={heritage_turkic} }   # 仅突厥
count_tribal_male        = { tier=county governments={tribal_government nomad_government wanua_government} priority=16 }
count_feudal_male        = { tier=county governments={feudal_government} }
```

  主角文化模板 `japanese`（heritage 非突厥）→ 游戏命中 `count_tribal_male`，本地化值 **酋长**（女性「女酋长」；公爵级 `duke_tribal_male=大酋长`）。即游戏显示 **可萨田所部酋长**。

### 3.2 代码口径与根因

| 位置 | 现状 | 应为 |
| --- | --- | --- |
| `facts.py:1013-1015` `_name_at_date` | `title_history_names` 最近名 → 回退 `custom/name` | 游牧头衔优先 `specific_title_name` |
| `facts.py:931-932` `title()` | `custom or name` | 同上 |
| `facts.py:1359-1360` `title_base_name` | `custom or name` | 同上 |
| `facts.py:1409-1466` `_office_word` | 无游牧分支；`count_nomad_male` 键不存在 → 回退 `count_feudal_male` = **伯爵** | 非突厥 heritage 命中 `count_tribal_male` = 酋长（公爵级 `duke_tribal_male`） |
| `cache_lib.py:1298-1319` `player_title_history` | 记 `custom or name` = 也勒克河 | 记 `specific_title_name` = 可萨田所部 |

因此 `official_title(38682)` → 「也勒克河伯爵」，写进人物档案首行；`历任`/`直辖` 同样用的是静态名。

### 3.3 附带发现（同一根因下的三处小错）

0. **伊斯兰动态国名与游牧政体互斥（用户指正，已核实）**：`Facts.realm_name`（`facts.py:2501-2518`）按「信仰→伊斯兰 + 家族名 + 层级词」拼「田所苏丹国 / 田所哈里发国」，在 `title()`（943）、`official_title()`（1663）、`prince_title()`（1931）三处**优先于**头衔名返回。该规则只对封建/氏族一类政体成立；`nomad_government` 用 `uses_culture_and_house_head_named_realms = yes`（`common/governments/00_government_types.txt`，全政体仅此一家为 yes），国名走 `$CULTURE_COLLECTIVE$$DYNASTY_NAME$部`，与伊斯兰国名互斥。
   - 本测试集暂未暴露：主角只持 `c_` 头衔，`realm_name` 只认 `k_/e_/h_`（2507 行），所以返回空。**但问题 3 一修就会踩到**——若主角日后以游牧之身取得王国/帝国头衔，`realm_name` 会在 `official_title` 里抢先返回「田所苏丹国」，把游牧动态头衔整个盖掉。
   - 修复：`realm_name` 开头加政体门 —— 持有者政体为 `nomad_government`（即带 `uses_culture_and_house_head_named_realms`）时返回 `""`，走游牧命名链。是否一并排除 `herder_government` / `tribal_government` 见决策点。

1. **`历任` 只显示营地、不显示领地**：`_primary_group`（`facts.py:1125-1155`）把 `x_` 营地当作「major」而 `c_` 伯爵领（rank 2）不算，主角「伯爵领 + 游牧营地」时 `majors=[营地]` → 历任只出现营地，891 年取得也勒克河/巴赫穆特两领完全没进履历（prompts.log 40533）。
2. **游牧营地被标成「无地冒险者营地」**：`facts.py:1243-1246` 对全部 `x_` 头衔追加该标注；`_camp_holder_word`（1315-1327）又拿冒险者宗旨史（缓存 `camp_purposes=[{880, brigands}]`）拼出「头目」，于是出现「田所游牧营地头目（无地冒险者营地）」。游牧营地 `x_c_nomad_*` 是毡帐驻地，不是冒险者营地。

### 3.4 修复方案（建议）

1. `_name_at_date` / `title_base_name` / `title` 增游牧分支：`gov ∈ {nomad_government, herder_government}` 且 `specific_title_name` 非空时用它；此时**不再追加层级词**（游戏不写「可萨田所部伯爵领」）。
2. `_office_word` 增游牧/部落分支，按游戏 flavorization 优先级查词：
   - 先 `f"{tier}_nomad_{male|female}_{heritage}"`（如 `count_nomad_male_turkish`）；
   - 再 `f"{tier}_tribal_{male|female}"`（`count_tribal_male`=酋长 / `duke_tribal_male`=大酋长）；
   - 最后回退现有逻辑。
   - heritage 从 `culture_manager.cultures[*].heritage`（或文化支柱）取，缺省视为非突厥。
3. `_primary_group`：持有领地头衔时，`x_c_nomad_*` 不进 major 组（游牧营地作为驻地单列或省略），让 `历任` 正常出现「可萨田所部酋长」「巴赫穆特酋长」等阶段。
4. `x_c_nomad_*` 不再追加「（无地冒险者营地）」，营地称呼词改按毡帐/游牧口径处理（或直接不渲染称呼词）。
5. `player_title_history` 同步改用 `specific_title_name`（这是 v4 就有的玩家主头衔名史，供信封/展示用）。
6. `realm_name` 加游牧政体门（见 3.3-0）：游牧统治者一律走 `specific_title_name + 部落/游牧官职词`，不出现「田所苏丹国」。

**决策点**：是否把 `specific_title_name` 优先扩展到**所有** dynasty/culture 命名头衔（实测 melt_900 有 423 个标题 `specific_title_name != name`，如 `k_croatia` 显示「马扎尔」、`c_knin` 显示「马扎尔齐奇部」）。扩展更贴游戏，但改动面大；建议**先只做游牧/牧民**，其余留作后续。

## 问题 4：牧群没传给模型

### 4.1 数据在哪

`melt_900` 顶层 `domiciles.database["1236"]`：

```json
{"domicile_type": "yurt", "owner_title": 19055, "provisions": 0,
 "herd": 715.69068, "culture": 198, "faith": 80, "province": 557}
```

`owner_title=19055` 正是主角 `landed_data.domain` 里的 `x_c_nomad_1565`（田所游牧营地）。逐档扫描牧群：

```
880–891（无地冒险者）  0
892  178.5   893  202.4   894  183.0   895  129.8
896  503.2   897  339.2   898  225.2   899  265.7
900  715.7   901  697.0
```

游戏 UI 键 `THE_GREAT_STEPPE_WINDOW_NOMAD_LABEL = @herd_icon!#V [Character.GetHerdAndRaisedHorde|0]#!`，即「牧群 716」。

### 4.2 根因

- `cache_lib.extract_snapshot` 只从 `landed_data` 取 `domain/became_ruler_date/government/realm_capital/vassal_count/council/laws/succession/strength/max_power`（`cache_lib.py:1441-1453`），**从不读 `domiciles`**（全项目 grep 无 `domicile` / `herd`）。
- 于是提示词政体句只有「政体游牧制，…直辖5地…，封臣0人，御前会议六席。」（prompts.log 40529），模型无从得知牧群。

### 4.3 修复方案（建议）

1. `extract_snapshot` 对玩家补取 domicile：以 `landed_data.domain` 中的头衔为 `owner_title` 匹配 `domiciles.database`（或按「该 title 的 holder == 玩家」匹配），写入 `rec["landed"]`：
   - `herd`（牧群）、`provisions`（口粮）、`domicile_type`、`domicile_province`。
2. `facts` 主角档案 `p["herd"]` / `p["provisions"]`；`biography._profile_lines` 政体句追加「牧群716」（口粮有值且非 0 时并写）。
3. **可选**：像 `player_locations` 一样记牧群变化点（`cache["player_herd_history"]`），在十年传时间线里写「牧群由129增至503」之类的经营线。需你确认要不要（会增加提示词体积）。
4. 牧群是玩家中心的缓存，只存主角即可；其它游牧角色的牧群暂不需要。

## 问题 5：模型没 get 到主角改信伊斯兰教

### 5.1 数据

逐档扫描主角 `faith`：

```
880–895  faith = 21  →  法华宗（pundarika，日式佛教）
896–901  faith = 80  →  艾什尔里派（ashari，伊斯兰）
```

即**改信发生在 895 年内**（895.1.1 档仍是法华宗，896.1.1 档已是艾什尔里派）。同年关系：896.10.17 娶第三房京代什（33589060，信仰 80 艾什尔里派、文化 198 可萨），毡帐 `domicile.faith` 也是 80。

### 5.2 根因

| 位置 | 现状 |
| --- | --- |
| `cache_lib.py:1374-1380` | `if c.get("faith") is not None: rec["faith"] = c["faith"]` —— 覆盖式写入，**无历史** |
| `facts.py:2606-2621` `faith()` | 只返回当前信仰名 |
| `biography.py:408-409` | 档案只写「信艾什尔里派」 |
| `facts.py:3188` 「信仰皈依」模块 | 只挂 `completed_hajj_memory` / `picked_*_aspect_memory` |

游戏侧也查过：`melt_896` 全档 95044 条记忆里只有 4 条 `adopted_state_faith_memory`，主角一条都没有；主角 `alive_data.variables` 只有一个残留的 `discounted_faith_to_convert_to_var`（无日期）。**改信没有事件记录，唯一可靠来源就是逐档 faith 差分。**

### 5.3 修复方案（建议）

1. `cache_lib`：`char_record` 增 `"faith_history": []`；`extract_snapshot` 在 faith 变化时追加 `{"from": date_label, "faith": fid}`（同日多跳去重），仍保留 `faith` 当前值。
2. `facts.faith_history_lines(cid)` → 「法华宗（自880年起）；艾什尔里派（自896年起）」或「895年改信艾什尔里派（伊斯兰教）」。
3. 时间线补一条事件（归「信仰皈依」模块）：「895年，色鬼田所浩二改信艾什尔里派。」——注意 895 是**区间推断**（上一年档仍为法华宗），措辞需你定：
   - 方案 a：写「895年」（最像史书，误差 ≤1 年）；
   - 方案 b：写「至896年1月1日已改信」（严格但读起来别扭）。
4. 是否顺带记录 `culture` 变化（同一机制，主角本例未变）。

### 6.1 数据已经齐全

受害者的 `imprisoned`（含 `imprisoner`）与 `released_from_prison_memory` 都在缓存里；主角侧也有 `imprisoned_other` 记忆。实测主角处决/狱死案：

### 6.2 根因

- `facts.death_clause`（`facts.py:2332-2354`）/ `_death_sentence`（3130-3151）只输出死法；
- `biography._assassin_kill_lines`（`biography.py:561-611`）只输出死者行 + 亲缘 + 婚恋；
- 没有任何函数读取 `imprisoned` / `released_from_prison_memory` 的时间差。

### 6.3 修复方案（建议）

1. `Facts.imprison_duration(cid, date=None)`：
   - 取该角色自身 `imprisoned` 记忆中 `imprisoner == 主角`（或任意 imprisoner）的最近一次入狱日 `t0`；
   - 若 `t0` 之后有 `released_from_prison_memory` 且早于死亡日 → 视为已释放，不计时长；
   - 时长 = 死亡日 − t0；`≥ 1 年`才返回（你的要求），渲染为「四年半」或「4年」。
   - 受害者记忆缺失时回退主角的 `imprisoned_other` 记忆。
2. 呈现：
   - 死句：「库诺·阿恩施泰因死于893年2月17日，**被田所浩二囚禁四年半后**斩首。」
   - 刺客列传独立行：「囚禁：888年7月3日入狱，893年2月17日被处决（囚4年6个月）」。
3. **决策点**：
   - 范围只限 `death_execution`，还是也含狱中死亡（折磨/饿毙/囚毙）？建议**含**，田所就有伊博尧 5.2 年一例，很有戏。
   - 阈值就用 1 年（居内什 1.0 年刚好卡线，需要定 `≥1` 还是 `>1`）。
   - 时长粒度：整年（「四年」）还是到月（「四年六个月」）。建议整年到月。
