## 问题 1：李漼在十年传里变成「唐秦皇帝 / 秦皇帝」——死者官职按 as_of 取国号

### 1.1 现象与证据

十年传（`田所浩二(843)_传记_第1个十年_878_01_01.md`）与终传里出现：

```
死者：秦皇帝李漼（死于874年8月15日，消失无踪。）      ← 提示词原文，logs/prompts.log
死者：秦皇帝李儇（死于874年11月6日，被田所浩二秘密谋杀。）
死者：秦皇帝李文举（死于875年1月24日，被田所浩二谋杀。）
死者：秦皇帝李润（死于875年6月23日，被田所浩二秘密谋杀。）
```

模型于是写出「**秦皇帝李漼**」（十年传 203 行）、「**唐秦皇帝李漼**」（终传 269 行，「唐」是它自己从上下文补的，于是拼成不存在的复合国号）。

### 1.2 根因（已定位到 `official_title` 的日期锚点）

`h_china`（头衔 id 14036，霸权级中华皇朝）的国号是**动态国号**，随王朝更替改名。实测 `melt_878` 的 `title_name_data.title_history_names`：

```
618.6.18  → dynn_title_tang  = 唐
875.6.25  → dynn_title_qin   = 秦     ← 崔慎由 875.6.23 夺位后两天改名
```

五位李氏皇帝全部死于 **875.6.25 之前**（李漼 874.8.15、李儇 874.11.6、李文举 875.1.24、李伯玉 875.4.8、李润 875.6.23），生前都是「唐」；国号改「秦」是崔氏的事。

但 `Facts.official_title(cid)`（facts.py:1490）取地名时走 `_last_title_place`（facts.py:1391），其内部一律用 **`self.as_of`**：

```python
# facts.py:1412 / 1445
return self._name_at_date(tid, self.as_of) or self.title_base_name(tid)
```

十年传的 `as_of = 878.1.1`、终传 `as_of = 879.8.9`，此时 `h_china` 早已叫「秦」，于是所有死于改名前的皇帝都被追认为「秦皇帝」。

实测（`experiments/research_office_date.py`，只读）：

```
李漼  death=874.8.15   as_of=>秦皇帝   death-date=>唐皇帝
李儇  death=874.11.6   as_of=>秦皇帝   death-date=>唐皇帝
李文举 death=875.1.24  as_of=>秦皇帝   death-date=>唐皇帝
李润  death=875.6.23   as_of=>秦皇帝   death-date=>唐皇帝
```

调用点（`official_title` 全部 5 处）：

| 行号 | 调用点 | 主体是否已死 |
| --- | --- | --- |
| facts.py:3615 | 主角档案 | 在世 |
| facts.py:3867 | `_character_profiles` 人物档案 | 活/死皆有 |
| facts.py:4330 | 奸夫谋夫模块（受害者） | 已死 |
| facts.py:4598 | **刺客列传击杀名录（本次病灶）** | 已死 |
| facts.py:2479 | `_office_name` 宫廷任职 | 活/死皆有 |

另外 `_last_title_place` 的 `dead_data.domain` 兜底分支（facts.py:1459–1487）**本来就用死亡日**（`died`），只有 `dead_data.flavor` 主分支用 `as_of` —— 这是 v24 修「汤利问题 6」时引入的内部口径不一致。

### 1.3 修复方案（推荐 A：死者按卒日、生者按 as_of）

给日期锚点显式化，**已死角色用卒日国号，在世角色维持 as_of**：

1. `_last_title_place(self, cid, fkey="", date=None)`：内部 `_name_at_date(tid, date or self.as_of)`；
2. `official_title(self, cid, date=None)`：
   - `date` 显式传入时用它；
   - 未传时，若缓存有 `death.date` → 用卒日；否则用 `self.as_of`；
   - 透传给 `_last_title_place`。
3. `_killed_by_player`（facts.py:4598）显式传 `(prof.get("death") or {}).get("date")`，与同函数里 `name_with_regnal`、`prince_title` 已有的卒日口径对齐。
4. 历任/朝局（`_primary_group` / `held_titles` / `_realm_facts`）**不动**：那是「头衔沿革」，仍按 as_of 现名。

改动量约 15 行，不动数据结构。

**副作用（需用户确认）**：这会改掉 v24「汤利问题 6」的既有行为 —— `official_title(15285)` 由「秦王王言」变为「翟王王言」（王言 891.6.3 卒，k_guannei 891.6.27 才改名「秦」，卒时国号是「翟」）。README:168 与 `docs/研究_汤利五问题.md` 问题 6 的记述需同步更新。两案口径天然冲突（一案要「游戏当前显示」，本案要「卒时历史」），我按**卒时历史**统一，请确认。

**备选 B（最小改动）**：只让刺客列传名录（facts.py:4598）传卒日，其余保持 as_of。田所两篇即刻修好，汤利案零影响；代价是同一篇传记里死者官职可能出现两种国号口径（本测试集实测未出现）。

## 问题 2：暗杀死法只有「消失无踪 / 被秘密谋杀」——建一个东西方暗杀死法池

### 2.1 现象与数据

玩家 32 次击杀的死因键分布（缓存实测）：

```
death_mysterious     24   → 「被X秘密谋杀」
death_disappearance   4   → 「消失无踪」（凶手被整句丢弃）
death_murder          3   → 「被X谋杀」
death_execution       1   → 「被X斩首」（v22 处决方式已修）
```

即四类死因只映射出两个词。更糟的是 `death_disappearance` 不在 `_DEATH_KILLER_VERB`（facts.py:335）里，`_death_clause`（facts.py:419）拿不到动词就退回裸死因，**凶手名整个消失**——李漼明明是浩二所杀，提示词却只写「消失无踪」，模型只好自己编「失踪于宫中」。

### 2.3 池子设计

**数据源 = 游戏本地化为主 + 史实补充为辅**

1. **游戏池（主）**：直接复用 `death_*_killer` 键的中文文案，把 `[TARGET_CHARACTER.GetUINamePossessive]` / `[TARGET_CHARACTER.GetUIName]` 替换为凶手名、`[CHARACTER.GetHerHis]` 替换为「其」。已实测可用的候选（节选）：

   | 键 | 渲染 |
   | --- | --- |
   | `death_poison_killer` | 被X毒死 |
   | `death_drowned_killer` | 被X溺死 |
   | `death_defenestration_killer` | 被X掷出窗外 |
   | `death_smothered_by_downy_robe_killer` | 被X下令捂死在一件毛茸茸的礼袍里 |
   | `death_too_much_dessert_killer` | 被X喂下有毒的甜点 |
   | `death_strongest_potion_killer` | 喝了X制作的过于强劲的药水 |
   | `death_treatment_killer` | 死于X的拙劣治疗 |
   | `death_disappearance_killer` | 在X的命令下消失得无影无踪 |
   | `death_disappeared_into_slave_markets_killer` | 在遥远的异域被X卖掉，不知所踪 |
   | `death_fall_in_hole_killer` | 被X推入一个洞中 |
   | `death_nailed_in_cabinet_killer` | 被X钉在一件家具上活活饿死 |
   | `death_starved_killer` | 被X饿死 |
   | `death_manhunted_killer` | 被X搜捕并杀死 |
   | `death_assassination_killer` | 被X刺杀 |
   | `death_murder_feast_killer` | 在宴会中被X下令杀死 |
   | `death_bell_killer` | 被X斩首，脑袋做成了钟舌 |
   | `death_by_artifact_killer` | 被X用一件宝物杀死 |
   | `death_thrown_off_kathisma_killer` | 被X的特工从皇帝专席上抛下身亡 |
   | `death_hunting_mysterious_killer` | 在狩猎期间于神秘情况下被X杀死 |
   | `death_dragged_killer` / `death_trampled_killer` / `death_torture_killer` / `death_whipping_killer` / `death_piteously_cut_down_killer` | 拖行/踩死/折磨/鞭死/砍倒 |

2. **史实池（补）**：游戏缺的东方风味与少数西方手法，按上面研究手写短语（`{k}` 占位凶手名），约 20 条，例如「被X遣人奉鸩酒赐死」「被X使人以丝绳缢杀」「被X遣刺客藏匕首于书卷中刺死」「被X以毒针刺入要穴」「被X装入麻袋沉入河中」「被X以毒戒指将毒药投入酒中」。

**每条池子条目带四个标签：**

```python
("poison_wine", "被{k}遣人奉鸩酒赐死",
  frozenset({"covert"}),   # 痕迹: covert=不留伤痕 / overt=见血张扬 / vanish=尸骨无踪
  "east",                  # 文化圈: east / west / any
  False)                   # 幼童可用
```

**可用性门（按死因 + 文化 + 年龄）：**

| 死因键 | 允许的痕迹标签 |
| --- | --- |
| `death_mysterious` | covert ∪ vanish |
| `death_disappearance` | vanish（必须尸骨无踪） |
| `death_murder` / `death_murder_known` / `death_assassination` | covert ∪ overt |
| `death_poison` | 仅 poison 类 |
| 其余（决斗/战死/病亡/处决…） | **不进池**，维持原样 |

- 文化圈：凶手或受害者文化属 `_ASIAN_HERITAGE_TPL`（facts.py:388，已含汉/和/朝鲜/回鹘等）→ 东方池 + `any`；否则西方池 + `any`。
- 年龄：受害者卒时 < 8 岁 → 只取 `幼童可用` 的条目（闷杀/毒杀/溺死/失踪），避开宴会、政变、围猎等成年场景（本案李文举 5 岁、李伯玉 3 岁）。
- 稳定伪随机：`md5("assassin::{凶手}:{受害者}:{日期}:{死因}")` 取种，与 `execution_method`（facts.py:2066）同法 —— 同一案重跑不漂移，不同案有变化。
- **游戏已记录具体死法者优先**：死因不是上述泛化键（例如存档直接给了 `death_defenestration`），仍按存档原样渲染，池子不覆盖事实。

### 2.4 集成点

1. `facts.py` 新增模块级 `_ASSASSINATION_METHODS` 池 + `_METHOD_REASON_TAGS` 映射；
2. `Facts.assassination_method(killer_id, victim_id, date, reason_key)`（仿 `execution_method`）；
3. `Facts.death_clause(cid, date=None)` 统一入口：处决走 `execution_method`，暗杀类走池子，其余走既有 `_death_clause`；
4. 替换 4 个 `_death_clause` 调用点：`_death_sentence`（facts.py:2906，覆盖刺客列传死者行/时间线/终传）、`_killed_by_player` 熔件兜底（4573）、主角死亡句（3750）、`player_death.reason_zh`（4846）；
5. `biography.py` 刺客列传中段 req（SECTION_REQ，biography.py:129–132）补一句正向引导：「死因按资料所写的具体死法原样书写」——只加正向要求，不出现否定词。

**不做的事**：不动 `death_execution` 的既有处决池；不动 `successful_murder` 摘要行（年表里「谋杀李漼」是记忆模板，去重合并后塞不下死法，且属另一处已有逻辑）。
